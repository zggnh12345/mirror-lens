## 3. 9.5 AB-1～AB-5 P0 专项核验（任务书 3.3）

### AB-1 请求级令牌（2949–2954）

- 现有实现：`gateway.go:857-858` `var claimed atomic.Bool; claim := func() bool { return claimed.CompareAndSwap(false,true) }`，在 fetchRace 内构造（862 赋给 plan.Claim），提交点 1531。**请求级回调式令牌已落地**，作用域为单次请求所有竞速 attempt（与 AB-1 目标一致）。
- 架构目标：请求级、覆盖跨站所有 attempt、令牌创建不依赖 A 特有前提。
- 3.5.17 新建：`atomic.Bool` ≠ Identity Claim。F19 要求 ClaimKey=(RequestScope,Identity) 跨链所有权、Reserved/Dispatched/Released 状态，此为新建，非现状。
- 结论：AB-1 的「请求级令牌」目标由现状部分满足（回调令牌存在），但其语义远弱于 F19 Claim。AUD-02（现状令牌被新 Claim 覆盖）+ AUD-03（不得把 atomic.Bool 描述为跨链 Identity Claim）。

### AB-2 CacheKey 适用层（2956–2959）

- 现有实现：`RegistryCacheKey(epoch,"manifest",ref)`（registry.go:340,372）按 origin，无新增键类型。
- 架构目标：A 不改 origin 维度；B 为新增键类型（按已验证逻辑身份）。
- 结论：AB-2 目标是清晰的分层约束，现状只实现 A 层。AUD-01（吸收为目标约束），并记录 B 键类型为待建。

### AB-3 FlightKey 策略枚举（2961–2964）

- 现有实现：`adapter.Plan.FlightPolicy string`（adapter.go:131-135）+ `flightKeyFor`（registryrace.go:48-55，`CacheKey+"\x00policy="+FlightPolicy`）+ 两档 `flightPolicyNoRace`/`flightPolicyRace`（registryrace.go:224,232）。命名空间已可扩展，但仅站内两档。
- 架构目标：预留 `cross-registry-*` 命名空间；嵌套 Flight 由 B 定义。
- 结论：AB-3 的可扩展枚举目标已落地机制（string 策略+键拼接），B 档位待加。AUD-01。

### AB-4 术语区分（2966–2969）

- 现有实现：`officialOnly(host,foreign)`（registry.go:417）、`OfficialOnly` 字段、1.6:2133「官方源不得成为竞速候选」；`out` 是文档术语，代码以 OfficialOnly 直连体现。
- 架构目标：`out`（官方直连 Source）与「权威 Registry」（Host）是两个对象，B 过滤链须区分 Source 语义与 Host 语义。
- 结论：AB-4 分层原则有效，现状有对应的 OfficialOnly 机制但未直接以 Host/Source 分层组织 B 候选。AUD-01。

### AB-5 可变 Tag 分层不互推（2971–2978）

- 现有实现：registryrace.go:184 T43 注释「可变 Tag 一律不进竞速」；`TestRaceTagNotRaced`；acceptance:34,74 实证。A 仅 digest 竞速成立。
- 架构目标：A 的 Tag 限制独立冻结；B 的 cross-registry-tag-race 是 B 自己的 policy，不得反推 A；2977「A、B 共享底层执行机制——attempt 生命周期、Scheduler、Lease、Body 校验、Claim、Cache commit」。
