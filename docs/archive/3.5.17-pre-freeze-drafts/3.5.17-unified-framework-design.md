## 1. RequestScope

- 定义：一个逻辑 HTTP 请求的统一执行上下文，持有全部 Chain、Attempt、共享预算、取消信号。
- 生命周期：请求入口创建 → 所有链/Attempt 注册 → 请求结束（成功/失败/取消）关闭。
- 创建/关闭：每个逻辑请求恰好一个；B/fb/Authority/Hedge/Midfill 不得各自创建独立 RequestScope（挂靠主请求的 scope）。
- 请求级状态：`scope_id`（唯一）、`budget`（AttemptBudget）、`registry_map_snapshot`（F08 静态抑制快照，请求开始时固定）、`claims`（本请求 Claim 集合）、`cancelCtx`。
- 取消传播：`cancelCtx` 取消 → 所有 Chain 进入 Closing → 所有 Dispatched Attempt 收到 Done → Body 关闭 → G/Source Lease 幂等释放。

## 2. Identity Claim

- `ClaimKey = (RequestScope, Identity)`；`Identity = (规范化 Registry, Repository, ManifestIdentity)`。
- Registry 规范化：`NormalizeHost`（allowlist + 小写 + 去默认端口）；Repository 规范化（小写、去 tag/digest、路径分段校验）。
- ManifestIdentity：Digest 请求 = digest 字符串；Tag 请求 = tag + Accept 协商语义（content-type/media type 参与身份，认证上下文不参与）。
- 认证上下文：不参与身份等价，但继续影响凭据选择/授权策略（与 11.3 一致）。
- 竞争规则：
  - 跨 Chain 同 Identity：原子竞争，只一条 Chain 获得 Claim（CAS on ClaimKey）。
  - 同 Chain 多 Attempt（A 站内多 Source）：共享 Claim，可并发。
  - 静态抑制优先于 Claim 可用性：F18 快照确定的抑制目标不参与 Claim 竞争。
- 状态：Reserved（预留）/ Dispatched（已发送）/ Released（释放）。
- 释放条件（第11章固定）：`ReleaseClaim = ChainClosed ∧ ActiveAttempts=0 ∧ ¬AnyAttemptDispatched`。
  - 不得因 Dispatched 请求成功/失败/取消而提前释放 Claim。
  - ChainID 是持有者身份，**不进 ClaimKey**（避免废掉 A 站内竞速/跨链去重）。

## 3. Chain

- 覆盖：main Chain、B 每 Registry Chain、Docker fb Chain；A 在 main Chain 内的 Source Attempt；Hedge/Midfill 归属到触发它们的 Chain（main/fb）。
- 生命周期：Open（可注册 Attempt）→ Closing（禁止新增、等待已注册退出）→ Closed（完全结束）。
- Closing：禁止 `RegisterAttempt`；等待所有 Attempt 退出（Completed/Aborted）。
- Closed 后禁止继续注册；触发 Claim 释放条件检查。

## 4. Attempt（两阶段预算 + 四态 + 发送门控）

- 状态（第11章四态）：Prepared（已注册、未越发送边界）/ Dispatched（已越过）/ Aborted（提交前退出）/ Completed（Dispatched 后路径结束）。
- 转换：
  - `Prepared → Aborted`：取消发生在提交前，释放 ReserveR，不消耗正式 R。
  - `Prepared → Dispatched`（发送门控）：`CommitR` 提交 R，进入 Dispatched，申请 G Lease。
  - `Dispatched → Completed`：执行结束，幂等递减活动计数、释放 G/Source Lease、Body 关闭；不返还 R。
  - `Dispatched` 后不得回退 Aborted；不论结果都不返还 R。
- 发送门控：实际 `g.cli.Do(req)` 前必须完成 Dispatched 提交，且与 Context 取消**同步仲裁**（取消与发送竞争时，用同一把锁判定：已提交则发送且不返还；未提交则 Aborted）。
- 两阶段预算：`ReserveR`（原子预留，Prepared）/ `CommitR`（正式消耗，Dispatched）。
- 每个真实上游 HTTP 请求 = 一个独立 Attempt（防止 Hedge/Midfill 在逻辑 Attempt 内偷发物理请求）。

## 5. AttemptBudget

- 单请求累计上限 R（见 budget-audit.md）；所有路径共享，无第二套预算。
- 逻辑 Attempt 与物理请求：`g.cli.Do` 一次 = 一次 Dispatched = 消耗 1 R。
- Hedge 额外请求：独立 Attempt，计入 R（口径待裁定，见 budget-audit §1.4）。
- Midfill 换源：首段/分片各独立 Attempt 计入 R；探活建议独立 R_probe 配额（不进 R，进 G）。
- B16 重试：每次额外网络 Attempt 计入 R（已含 `(A+1)`）。
- Authority：`R_authority=1`。
- fb：`R_fb≤3`，按实际 Dispatched 累计。
- 预留失败/取消/异常退出：Prepared 取消释放预留；Dispatched 取消不返还；Completed 幂等只递减一次。

## 6. RegistryRetryToken（第四层，独立于 Claim/tried/Budget）

- 每次顺序访问某 Registry 最多一个令牌，绑定「本次顺序访问 + Registry」。
- 只授权一次额外网络 Attempt（B16）；不预留 R、不代表 Attempt 已发生。
- 不跨 Registry、不跨逻辑请求转移；不释放 Claim、不清空 tried、不创建新 RequestScope。
- 重试持有原 Claim；重试不能绕过 R/G。
- 首轮跨站竞速参与的 Registry 不创建/不消费令牌。
- 消费后不可恢复。

## 7. GlobalLeasePool

- G 具体数值待裁定（budget-audit §2.3）；本设计固定机制不填数值。
- 层级：G Lease（全服务）在上，Source Scheduler Lease（单源）在下；先 G 后 Source，释放逆序。
- 申请/释放：Dispatched 前申请 G，Completed/Aborted 幂等释放；部分失败回滚（G 成功 Source 失败 → 释放 G；G 失败 → 不申请 Source）。
- 取消在两申请之间 → 释放已获 G。
- Body 结束/换源/取消 → 幂等释放（复用 leaseBody/wrapLease retire 回调）。
- Hedge/Midfill 双重计数防护：每 Attempt 申请一次 G，禁止同物理请求申请两次。
- 禁止把 Source Lease 改名为 Global Lease（层级不同）。
