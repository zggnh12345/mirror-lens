## 版本定位与核心目标

3.5.17 在 3.5.16 同 Registry Source 竞速（A）基础上，增加受可信映射约束的跨 Registry 可信副本发现、身份验证、顺序回退与跨站竞速，最终形成 A+B 两级调度。

职责分工（冻结）：
- **B**：决定哪些 Registry 可参与同一逻辑资源请求，以及跨站执行策略（顺序回退 / 跨站竞速）。
- **A**：每个 Registry 内部的星标 Source 竞速。
- **Scheduler**：单 Host 的 Source 选择、健康过滤、并发准入、Lease（不变）。
- **统一执行层**：请求级并发预算、Attempt 生命周期、唯一提交、资源释放。
- **缓存层**：按已验证的逻辑资源身份决定缓存归属。

## 一、三个独立控制域（冻结）

| 控制域 | 功能 | 默认状态 | 控制范围 |
|---|---|---|---|
| A | 同 Registry Source 竞速 | **关闭**（恢复，与 3.5.16 已发布行为一致） | Host 级 star_race + Source 星标 |
| B | 跨 Registry 调度 | 顺序回退（竞速模式默认关闭） | **无 B 总开关**，仅模式选择 |
| Realm | 额外 Realm 授权 | 关闭（无全局开关） | 现有 `source_realm_policy`（Source × Host） |

**裁定要点：**
- A 默认**关闭**：Host 总开关默认关、未配置视为关；星标仅代表人工竞速资格，不自动开启；只有 Host 开关开且有合格 Source 才执行站内竞速。**3.5.17 不得通过配置迁移、UI 默认值或 B 的启用间接开启 A。**
- B **删除总开关**，保留模式选择：默认顺序回退；跨站竞速为显式选择。没有可信映射时自然退化为既有单站行为。**不存在「关闭 B 后整个 B 不工作」。**
- Realm **不新增**任何全局启停开关，也不新增每个 Realm 的 enabled 字段。额外 Realm 本身即允许列表，删除条目即撤销授权；删除整个策略运行时 fail closed。Realm 授权语义由现有策略内容决定（primary_realm / extra_realms / policy_gen），与 Registry 多源开关是不同类配置。
- A、B、Realm 独立启停；关闭或变更任一方不得改变另外两方行为；Realm 额外授权关闭不等于关闭既有 Realm 校验。

### A+B 四种组合（按「模式」重述）

| A（Host 级） | B 模式 | 执行行为 |
|---|---|---|
| 关闭 | 顺序回退 | 跨站顺序回退，每站内部顺序选择 Source |
| 开启 | 顺序回退 | 跨站顺序回退，每站内部可使用 A |
| 关闭 | 跨站竞速 | 跨站并行，每站内部顺序选择 Source |
| 开启 | 跨站竞速 | 跨站并行，每站内部可使用 A |

任何组合都不改变既有 Blob 执行路径。

## 二、功能边界

### 2.1 交付

- B 模式选择（顺序回退 / 跨站竞速），无独立总开关。
- 显式可信副本映射管理（精确到仓库）。
- 有前缀与无前缀请求统一进入 B 的路由协调入口。
- Digest 与 Tag 的跨站资源身份验证。
- 固定排序与动态排序。
- 顺序回退；跨 Registry Manifest 竞速。
- 跨站候选上限冻结为 2；统一请求级 AttemptBudget。
- 请求级 Claim 与唯一提交；跨 Registry CacheKey 身份治理。
- Realm 策略管理沿用现有入口（不新增开关）。
- 管理界面、API、指标、日志、审计。
- G0 流式回归、并发安全、性能与故障恢复验收。

### 2.2 不交付

Blob 跨 Registry 竞速；自动搜索 / 发现未知 Registry；仅凭同名仓库推断可信副本；跨 Registry 凭据共享；重写 Scheduler / 通用代理协议 / 缓存系统；把 B 变成新的 Source 评分系统；docker.io/ghcr.io 独立多源开关。

## 三、功能优化内容

### 3.1 显式可信副本映射（P0 门禁）

映射必须明确两个 Registry 仓库是否为同一逻辑资源；同名不自动认定。映射至少含：权威 Host、权威 namespace/repository、副本 Host、副本 namespace/repository、映射来源、Digest 可信策略、Tag 是否允许跨站竞速、Tag 版本一致性依据、生效状态与有效期、创建/修改/删除审计。

- 精确到仓库，不允许配置一个 Host 即信任其上全部同名仓库。
- 禁止生成映射的行为：404 后猜测、owner/repository 同名、`rememberHost()`、Source 探测成功、某 Host 支持某协议。
- 存储模型待冻结（17a）：Schema / 唯一约束 / 索引 / 有效期 / 与 3.5.14c 零残留对齐。

### 3.2 有前缀与无前缀请求统一进入 B（修订 1.6 旧作用域）

两类请求**均进入 B** 的可信映射判断与调度：
- 无前缀：默认权威 Registry 为首选站；
- 显式前缀：前缀指定 Registry 为首选站。

两者仅在首选站认定上不同，都受同一套可信映射门禁与 B 模式约束；不能因显式指定 Host 绕过 B 或自动信任同名仓库；无可信映射时退回既有路由。实现复用 `ParsedPath` / `PlanParsed` 的 Host 身份解析，不字符串重解析。

> 配套 D1-A：1.6 第 2855 行整句重写，删除「只作用于无显式前缀」「按前缀直连、不受模式影响」。

### 3.3 固定排序与动态排序

- 名称统一：固定排序 / 动态排序。
- 固定排序：按管理员配置的 Registry 优先级逐个回退（docker.io → ghcr.io → quay.io → gcr.io → registry.k8s.io → public.ecr.aws → *.pkg.dev → registry.gitlab.com → mcr.microsoft.com → cgr.dev）。列表为可配置默认值，非不可改常量；只决定尝试顺序，不代表均为可信副本。
- 动态排序（裁定）：
  - **每条映射独立累计 50 个有效映射回源样本**，不同映射不得混合；
  - 未达 50 用固定排序，达到后允许动态排序；
  - 评分仅用成功率（60%）与响应延迟（40%）两维度；**调用频率权重 0%**，不参与评分（避免高频映射因流量大形成反馈循环）。
  - 保留固定顺序作失效兜底；配置变更 / 映射失效 / 样本异常时不得用过期排序；
  - 动态排序**不改变**可信映射关系，**不自动开启**跨站竞速。
- 样本口径（G3 已冻结）：每条映射独立维护最近 **50 个有效映射回源样本**（W1）；不足 50 用固定排序，达到后用动态排序，新样本进、最旧出；映射身份/可信关系变化则旧窗口清零。每次真实回源尝试最多计一样本，首站命中计入，缓存命中未回源不计入，本地准入失败/未发出候选不计入；成功须过 Manifest 身份验证；失败按失败分类计入；用户取消、客户端断开、策略/认证拒绝、本地准入失败、因其他候选胜出而取消均不计入。评分公式（W2 冻结）：`Score=0.6×SuccessRate+0.4×LatencyScore`，`LatencyScore=1/(1+P50(TTFB)/800ms)`；只有可测量 TTFB 参与中位数，无则 LatencyScore=0；不额外做时间衰减；并列按可信映射固定顺序兜底、不随机。

### 3.4 B 跨 Registry 竞速（裁定后参数）

**冻结参数：** 跨站候选上限 C=2（3.5.17 新冻结值，不可配置扩大）；每站 A 上限=2；投票宽限窗口初始 200ms（可配置，上线后实测标定）；动态样本门槛 50/映射。

~~原方案「最多 8 候选、首批 4 分支、最多 4 并发、8 Attempt」全部作废~~：不作为本版本冻结值。原方案的 4 并发 / 8 Attempt 属未冻结旧预算值。

执行原则：
- 候选按固定/动态排序，受 C=2 与统一 AttemptBudget 约束；
- 首批候选启动；某候选明确失败或释放名额，立即补入下一个；不采用僵硬两批屏障，也不因慢请求拖住后续；
- 任意候选身份验证失败不得获得提交资格；有效结果确定后取消其他候选并释放资源；
- 所有候选共享请求级预算，取消的 Attempt 释放预算，补位只用已释放预算；A、B 不各维护互不知情的并发计数。

### 3.5 请求级 Claim / CacheKey / 认证隔离（17a 冻结）

- **请求级 Claim**：现有 A 的 Claim 只解决站内提交，不能直接作为 B 跨站唯一提交。B 必须具备请求级 Claim：所有跨站候选共享同一 RequestScope；仅身份验证通过的候选可提交；任意时刻只有一个候选提交响应与缓存；失败候选不提前写最终缓存；赢家确定后取消其他候选、关闭未选中 Body、释放 Lease；不得复用会提前执行 `saveBody`/`settleTarget` 的成功路径。
- **两类 Claim 必须区分（详见冻结清单 F19）：** 上述"请求级 Claim"指**唯一提交权**（谁可写缓存）；F19 的"链级 Identity Claim"指**跨链去重**（哪条调度链可发起同一身份请求）。链级 Claim 以 `(RequestScope, Identity)` 为键、ChainID 仅为持有者：同链多 Attempt（如 A 站内多 Source）共享 Claim 可并发，跨链对同一 Identity（如 docker fb 与 B 的 GHCR 候选）原子竞争只一条发起。链级 Claim 不取代 `tried` 去重、AttemptBudget、A 竞速资格与重试限制。
- **FlightKey 与 CacheKey 分离**：分别定义请求合并身份与缓存身份；处理 Registry 原始身份、可信映射身份及代次、Tag/Digest 区别、Manifest/Blob 区别、Cache Epoch、旧缓存回收与 Janitor。不同 Registry 相同 Repo/Tag 不得共享未验证缓存身份。A 层 CacheKey 语义不变；B 层逻辑资源缓存键按「权威仓库标识 + 请求引用 + 已验证内容身份」归属（结构 17a 冻结）。
- **认证隔离**：跨站候选独立执行目标 Host 认证策略；不跨 Host 泄漏 Authorization；不跨 Host 复用未授权 Realm；不跨策略代次复用旧 Token；私有请求继续遵守共享缓存隔离；跨站竞速仅限可信映射验证后的 Manifest，不扩展到 Blob。

### 3.6 Realm 策略入口（沿用现有，不新增开关）

现有 `internal/store/policy.go` 已有 Source × Host 策略模型（primary_realm / extra_realms / policy_gen，上限 3，删策略 fail closed），策略更新联动清理 Host 能力、健康/恢复状态并通过代次隔离 Token Cache。授权语义：改主 Realm=改主授权，加/删额外 Realm=扩大/撤销，删整条策略=fail closed。**不新增全局开关、不新增每条 enabled 字段。** Web 管理缺口仅在于确保策略变更完整经过现有失效机制。

### 3.7 Registry 多源 Host 开关（保留现有，不重复开发）

`registry.multi_origin_hosts` 为 Host 级现有配置（Restart: true），Web 入口在 设置→配置参数→Registry 加速→多源 Host 开关（`MOH_HOSTS` 固定 8 个），Realm 页只读展示。处理原则：保留现有开关与 Web 入口；不新增第二套配置事实；不把 star_race、B 模式与 multi_origin_hosts 合并；不改热更新；多源开关只控制候选调度资格，不自动授予跨 Registry 信任、不自动开启 A 或 B 跨站竞速。固定范围外的自定义 Host 仍可能参与多源；该开关不影响官方直连。

### 3.8 顺序回退（失败分类沿用 1.6）

| 失败类别 | 恢复动作 | 回退 |
|---|---|---|
| 超时 / 连接失败 / 不通 | 本站立刻重试一次，仍失败再回退 | 是 |
| 404 / manifest unknown | 不重试 | 是（仅已配置候选，禁止猜测新站） |
| 401 / 403 | 不重试，下一站按公开身份请求 | 是 |
| 429 / 5xx | 不重试，遵循退避/冷却 | 是 |
| 无效 Manifest / Digest 不一致 | 不重试，丢弃响应 | 是；该候选不进投票/提交 |
| 身份验证失败（B.3 未过） | 不重试 | 否，不得自动获尝试资格 |
| 私有认证 / 安全策略拒绝 | fail closed | 否 |

不跨站携带凭据；下一站用自身认证策略。全部候选 MISS 时维持正确 404/原有错误语义。

### 3.9 Manifest 身份验证（沿用 1.6 B.3）

三层：仓库身份（明确映射）、Manifest 身份（请求期望 Digest / 响应 Docker-Content-Digest / 正文计算 Digest 三者一致，正确处理 media type / Accept / 多架构索引）、响应有效性。跨站投票：宽限窗口（初始 200ms）内 ≥2 候选通过三方校验且一致才确认；单候选与权威站 Digest 软比对，失败则回退权威站；窗口外不参与、不等待最慢者；全不一致判不同步回退权威站。资源身份可信 ≠ 认证身份可信，分别验证；B 继承 3.5.15 全部安全约束。

### 3.10 缓存身份与资源释放

A 层 CacheKey 不变；B 层按已验证逻辑资源身份归属：不同 Registry 的 Tag 默认不共享键；Digest 相同且验证通过可按内容寻址复用；Tag 仅在可信映射+版本一致性证明后共享逻辑身份；记录实际胜出 Registry/Source/验证依据；未验证候选不得写权威缓存；不直接删除 origin 维度实现跨站共享；覆盖命中、并发写、索引更新、Janitor、崩溃恢复测试。私有 Host 不进共享缓存、不因 B 回退绕过 OfficialOnly。

每个 Attempt 独立 Context；胜者确定后取消其他 Attempt、关闭 Body、释放 Lease、清理临时文件与未提交缓存、停止 goroutine；客户端断开/超时/Digest 失败/认证失败统一走清理路径。

## 四、并发预算（G / R / C / F / BSequential）

> 完整模型与状态机见冻结清单 `docs/3.5.17-freeze-checklist.draft.md` 第 4、6、7、9、10 节；本节为方案层摘要。**G、R 具体数值未在本方案填值**，由 17a 推导审查冻结。

### 4.1 两级预算（维度分离，已冻结）

| 项目 | G：全局预算 | R：请求级预算 |
|---|---|---|
| 作用范围 | 全服务 | 单个逻辑请求 |
| 限制对象 | 同时占用的上游尝试资源 | 单请求累计发出的上游尝试次数 |
| 控制机制 | 全局并发 Lease | 请求级 AttemptBudget |

- **删除 `R ≤ G`**（维度错误，无大小关系）；G 控并发、R 控累计。B 顺序回退、跨站竞速、A 站内竞速及 fb 均受二者限制。
- 每逻辑请求仅一个共享 AttemptBudget；每次真实上游请求前取得额度，额度消耗不返还，Lease 用后释放。
- `C=2`：跨站竞速单轮候选上限，只约束竞速、不约束顺序回退；顺序回退/权威兜底/A/fb 均消耗 R。
- `A`：单站 main 链并发路数——开启最多 2 路星标 Source，关闭取 **1**（不取 0）。
- `F`：当前请求中符合既有 fb 资格、已实际启动且未退出的 fb 链并发之和；每条最多 1 路（fb 链独立于 `star_race`，现有代码下仅符合 docker.io 条件者贡献）。`2×2+2=6` 仅为 1.6 历史示例，不作验收标准。
- `BSequential`：顺序回退路径任一时刻实际占用的 main 链并发资源，不是候选总数、不是累计次数（访问 5 站每次一个仍为 1）。

### 4.2 模式分支公式（原三项恒相加公式已废止）

| 模式 | A 开关 | GlobalUsage |
|---|---|---|
| 顺序回退 | 关闭 | `BSequential + F` |
| 顺序回退 | 开启 | `BSequential + F` |
| 跨站竞速 | 关闭 | `(C×1) + F` |
| 跨站竞速 | 开启 | `(C×2) + F` |

两模式为分支关系，非恒定叠加；竞速失败转顺序补位须先释放全部竞速 Lease 再按新状态申请。

### 4.3 R 最坏累计路径（规则冻结，数值未冻结）

`R_required = R_race + R_fallback + R_authority`，按真实 Attempt 累计（非并发数）。`R_race = Σ(R_main,i + R_fb,i)`；身份抑制只减少特定组合消耗，不降低 R 上限（至少按 fb 实际启动组合推导）。R 冻结值取所有允许组合最大值，17a 推导审查冻结。

### 4.4 F18 / F19 与数值冻结时机

- **F18（17a 冻结，含 M 数值）**：M = 可信副本回退链候选总数上限（含首轮 C=2）；权威站兜底独立于 M 但计入抑制快照；`B_snapshot = B_truncated(M) ∪ B_authority`（按 Identity 去重）。F18（含 M 数值）先于 F19 最终冻结。
- **F19（审查基线候选，未冻结）**：fb 适用范围保持现有 docker.io→GHCR 不扩展、独立于 `star_race`；静态抑制按请求引用+内容协商语义判 Identity 等价（Registry 取逻辑 origin）；链级 Claim `(RequestScope, Identity)` + Chain 状态 + Attempt 状态 + 发送门控 + R 两阶段（ReserveR/CommitR）+ Claim 释放 `ChainClosed ∧ ActiveAttempts=0 ∧ ¬AnyAttemptDispatched`。
- 冻结时机：**G、R 数值、F18、F19 正式冻结均在 17a**；17f 只按冻结数值验收实现，不重新决定数值。
