## 1. 设计目标与边界

F08 为 3.5.17 B 层建立「跨 Registry 可信副本映射」的权威数据。核心事实（第11章 + B.2 2682–2692）：
- 可信关系必须显式配置，禁止按同名 Repository/404/200/星标/参选勾选/rememberHost/GHCR fallback 自动建立。
- 一条映射表达：某权威 Registry 下某 Repository，允许由另一 Registry 下某 Repository 代表，及允许的 Manifest 引用策略。
- 与 `source_host_caps`（Source×Host 能力）正交：F08 是 Host×Repository 级信任关系，不是 Source 能力，不是 Source 星标。
- 权威站（乙案）独立于映射候选，不占 M/C。

## 2. 完整 DDL（新增 1 张主表 + 1 张版本/审计表，纳入 canonical.sql）

```sql
-- 3.5.17 F08：跨 Registry 可信副本映射
CREATE TABLE registry_trusted_mapping (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  authority_host     TEXT NOT NULL,      -- 规范化权威 Registry host（NormalizeHost）
  authority_repo     TEXT NOT NULL,      -- 规范化权威 Repository（去前导斜杠、小写、去 tag/digest）
  replica_host       TEXT NOT NULL,      -- 规范化副本 Registry host
  replica_repo       TEXT NOT NULL,      -- 规范化副本 Repository
  manifest_policy    TEXT NOT NULL DEFAULT 'digest_only',
      -- 合法值：digest_only | tag_and_digest（B.3 引用策略；可变 Tag 需 B 自身一致性证明）
  enabled            INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
  priority           INTEGER NOT NULL DEFAULT 0,  -- 固定顺序候选排序键（确定性截断 M 用）
  valid_from         INTEGER,            -- 生效起（Unix 秒，NULL=无起点）
  valid_until        INTEGER,            -- 生效止（Unix 秒，NULL=无终点）
  policy_gen         INTEGER NOT NULL DEFAULT 1, -- 每次更新递增，缓存/投票失效维度
  created_at         INTEGER NOT NULL,
  updated_at         INTEGER NOT NULL,
  CHECK (authority_host <> replica_host),
  CHECK (valid_from IS NULL OR valid_until IS NULL OR valid_from <= valid_until),
  CHECK (manifest_policy IN ('digest_only','tag_and_digest')),
  UNIQUE (authority_host, authority_repo, replica_host, replica_repo)
);

-- 固定顺序候选索引：按权威 + 优先级 + id 确定性读取（M=4 截断前）
CREATE INDEX idx_trusted_mapping_order
  ON registry_trusted_mapping(authority_host, authority_repo, enabled, priority, id);
-- 反查：某副本宿主被哪些权威映射引用
CREATE INDEX idx_trusted_mapping_replica
  ON registry_trusted_mapping(replica_host, replica_repo);

-- 映射变更审计（与 source_events 同风格，写路径同事务）
CREATE TABLE registry_mapping_events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  mapping_id  INTEGER NOT NULL,
  kind        TEXT NOT NULL,   -- create | update | delete | toggle
  detail      TEXT,            -- 变更摘要（不含凭据）
  policy_gen  INTEGER NOT NULL,
  actor       TEXT,            -- 操作者（API 层传入）
  created_at  INTEGER NOT NULL,
  FOREIGN KEY (mapping_id) REFERENCES registry_trusted_mapping(id) ON DELETE CASCADE
);
CREATE INDEX idx_mapping_events_ts ON registry_mapping_events(mapping_id, created_at DESC);
```

## 3. 字段合法性 / 状态字段

- `authority_host`/`replica_host`：经 `NormalizeHost` 语法规范化 + allowlist；不接受 IP/localhost/私网（复用 registry host 校验）。
- `authority_repo`/`replica_repo`：规范化（小写、去前导 `/`、去 `:tag`/`@digest`、路径分段校验），不允许含 `..`。
- `manifest_policy`：枚举 `digest_only`（默认，仅不可变 Digest 可信）/ `tag_and_digest`（可变 Tag 需 B 自身 Tag 一致性证明，不反推 A 的 T43）。
- `enabled`：0/1；停用映射不进候选（与 source caps.enabled 语义一致）。
- `priority`：确定性排序键；同优先级按 id 升序，保证截断 M 可复现。
- `valid_from/valid_until`：有效期；查询时过滤 `enabled=1 AND (valid_from IS NULL OR valid_from<=now) AND (valid_until IS NULL OR valid_until>now)`。
- `policy_gen`：每次 enabled/repo/policy/有效期变更 +1；缓存与投票快照按 generation 失效。

## 4. 唯一约束与去重

- 业务唯一键：`(authority_host, authority_repo, replica_host, replica_repo)`，防重复映射。
- 不限制同一权威对应多个副本（M=4 来自多条映射，按 priority 截断）。
- 一副本可服务多个权威（多对多），但每条映射独立 policy_gen。

## 5. Schema 版本与迁移

### 5.1 版本号与 hash
- 新 Schema 版本 `3.5.17`；更新 `schema.go:19 Version="3.5.17"`、`CanonicalSchemaHash` 重算（含新表结构 hash）。
- 新表加入 `canonical.sql`（embedded DDL），新库 `EnsureFresh("fresh")` 直接建全表。

### 5.2 迁移输入指纹
- 迁移基线：`schema_version=3.5.14` / hash `7e5d71a7…`（生产实测一致）。
- 前置条件：`schema_meta` 单行、结构 hash==Canonical、integrity_check=ok、备份单元已生成（DB+key+config+manifest）。

### 5.3 迁移执行顺序（离线 db-migrate，停服）
1. 停服 + FD 扫描 + 对 `.mirror-lens.lock` 取 flock。
2. 备份单元（`scripts/backup_unit.sh`，schema 3.5.14，含 95 sources/194 policy 行）。
3. 事务内：`CREATE TABLE registry_trusted_mapping` + 2 索引 + `registry_mapping_events` + 索引。
4. 回填：从配置/历史映射导入（若首次无映射，空表，不阻塞——无映射退回既有路由）。
5. 更新 `schema_meta`：version=3.5.17、schema_hash=新 Canonical、baseline_version=3.5.14、applied_at。
6. 写 `schema_migrations_audit` 一条迁移事实。
7. 提交；校验 integrity_check + 结构 hash + 版本。
8. 启动新镜像，运行时 `schema.Verify` 通过才对外服务。

### 5.4 迁移失败回滚
- 事务内失败：整体 rollback，DB 回到 3.5.14（新增表随事务消失）。
- 提交后发现不兼容：用备份单元恢复 3.5.14 DB+key+config，回退旧镜像（3.5.16 rollback 容器模式）。
- 备份单元必须可校验（manifest + sha256），回滚脚本默认只检查，`--apply` 才执行。

## 6. 降级与旧版本兼容

- 3.5.16 二进制读取 3.5.17 库：`schema.Verify` 因 version != 3.5.14 拒绝启动 → **必须靠备份库 + 3.5.16 镜像回退**，不支持就地降级读新表。
- 新表对 3.5.16 业务透明（3.5.16 不引用之）；但 schema 版本门禁会阻止混用，符合「部署期全局回退、不混用新旧框架」原则。
- API 未配置任何映射时，B 层退回既有路由（无映射不跨站发现），与 2857 一致。

## 7. 数据一致性验证

- 迁移后：`SELECT count(*) FROM registry_trusted_mapping`（记录条数）；`PRAGMA integrity_check`；`schema.Hash` == 新 Canonical；`schema_meta` 单行。
- 唯一约束：重复 `(authority,repo,replica,repo)` 插入应被拒绝。
- 有效期：过期映射不出现在候选查询。
- policy_gen：更新映射后 gen+1，缓存快照失效可观测。
