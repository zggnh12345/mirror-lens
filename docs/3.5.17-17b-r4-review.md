### 未判定为缺陷（记录判断依据）

- **Authority 失败后回到 `fetchOnce` 再发一次官方 Attempt**：不是第二个 AuthorityAttempt
  （`run(0)` 由 `sync.Once` 记忆化），而是 B.4「全部候选失败后按权威 Registry 原有错误
  语义返回」——`fetchOnce` 仍会先试该 Host 的镜像源再试官方。用量受 R=16 约束。
  若后续要求「权威失败即终止」，那是语义变更，需要单独定版。
- **race 模式下可变 Tag 请求需要一次官方派发**：B03 要求版本一致性，Tag 没有内容寻址
  身份，只能与唯一一次 AuthorityAttempt 对照。代价是该类请求多一次官方 RTT；
  收益是不会把过期 Tag 写进权威缓存键。digest 请求不需要（`TestReplicaDigestSkipsAuthority`）。

## 3. 性能（B15）

判定：**EXTERNAL_BLOCKED**。本轮没有任何真实外部 Registry 可用，端到端 P50/P95/P99、吞吐、
错误率都无从测量，不得写成 REAL_PASS。

进程内对照（`-benchtime=200x -count=5`，同机同负载配对，仅测跨站候选发现这一步）：

| 变体 | 5 组样本（ns/op） | 中位数 |
|---|---|---|
| B 关闭（默认空勾选） | 5993 / 6182 / 5986 / 6096 / 7859 | 6096 |
| M=4 全配置 | 118985 / 121728 / 138614 / 122811 / 123438 | 122811 |

结论只能说：B 关闭时每次冷 Manifest 多约 6 µs（一次设置读取），B 全配置时候选发现约
123 µs（1 次副本查询 + 1 次代次查询 + 每副本 1 次 Source 映射查询 + 调度器候选）。
相对一次上游 RTT（通常数十 ms）占比 <1%，**但这不代表端到端时延改善或达标**；
候选发现没有快照缓存，是本轮留下的可优化点（残留风险 R3）。
