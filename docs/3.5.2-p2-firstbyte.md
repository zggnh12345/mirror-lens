# P2-2 首字节竞态修复记录（独立提交，不计入 A1/A2）

- 分支：`feat/3.5.2-a1a2`
- 范围：`internal/gateway/watch.go` + `internal/gateway/firstbyte_test.go`
- 归属：3.5.1 遗留缺陷；是否纳入 3.5.2 发布门禁由最终发布范围决定


3.5.1 遗留、3.5.2 分支此前未修：`time.AfterFunc(3s, cancel)` 与
`resp.Body.Read` 并发，`Stop()` 返回 false 只说明回调已启动，不保证它没在
读首字节成功后取消 ctx，导致已接管的 body 中途断开。

修复（`internal/gateway/watch.go`）：

- `waitWithin`：超时回调只投递信号，不直接 cancel；「数据先到」与「超时」
  在同一个 `select` 里唯一胜出，两者同时就绪时优先取已到达的数据。
- 发送请求与读首字节各自等待，共用同一个预算；读首字节成功路径不再调用
  cancel，改为 `cancelOnClose` 在 body 关闭时取消，避免 context 泄漏。
- 超时后才返回的响应由清理协程关闭，避免连接泄漏。

测试（`internal/gateway/firstbyte_test.go`）：

| 用例 | 覆盖 |
| --- | --- |
| `TestWaitWithinTiePrefersValue` | 首字节与超时同时就绪：300 轮均判数据胜出，超时回调零调用 |
| `TestWaitWithinTimeoutCallsOnce` | 首字节未到：超时回调恰好一次，迟到数据不改写结果 |
| `TestTrySwitchKeepsBodyAfterFirstByte` | 成功接管后继续读完整 body（超时预算 40ms，剩余数据在 80ms 后才发） |
| `TestTrySwitchTimeoutBeforeFirstByte` | 首字节一直不来：放弃换源，不交付半开响应 |
