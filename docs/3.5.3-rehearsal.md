# 3.5.3 Phase B 实机演练记录

> 对象：生产库实时快照（3.5.1 运行中数据，91 个源 / 255 条 source_health）。
> 方式：`VACUUM INTO` 一致性快照 → 在本地副本上跑 3.5.3-rc1 镜像；生产容器全程未停、未改。

## 环境

- 快照：`/data/mirror-lens.db`（22,581,248 字节），`PRAGMA integrity_check = ok`，`journal_mode = delete`。
- 迁移前：`source_health` 255 行（docker 87 / ghcr 88 / github 80），`family='registry'` 0 行；
  无 `schema_migrations`、无 `source_health_archive`；`source_health_scope` 为 3 列 PK。
- 为验证归档路径，副本中人工植入 3 条 legacy registry 行（fails 2/3/4，源 ID 1/2/3）：
  生产实际已是 0 行，不植入就测不到这条分支。植入只发生在副本。

## 结果

| 步骤 | 结果 |
| --- | --- |
| 首次启动（3.5.1 → 3.5.3） | `candidates=3 archived=3 removed=3 left=0 already_done=false` |
| 归档内容 | 3 行，`source_id:fails` = 1:2, 2:3, 3:4，字段与源行逐一对应 |
| 迁移后运行表 | `family='registry'` 0 行；`source_health` 255 行（258−3），其他 family 未动 |
| 标记 | `3.5.3-phase-b-tables`、`b1-archive-legacy-registry` 各一条，同一秒写入 |
| 3.5.2 结构迁移 | `source_health_scope` 主键已变为 `(source_id, family, scope, gen)` |
| 服务健康 | `/healthz` 200 `{"busy":true,"ok":true}`，`/login` 200，`/api/health` 401（需鉴权，符合预期） |
| 二次启动（幂等） | `candidates=0 archived=0 removed=0 left=0 already_done=true`；建表 step 直接跳过 |
| 回滚（方案 A） | `Unarchive` → `restored=3 skipped=0`，运行表回到 3 行，`b1` 标记被同一事务删除 |
| 回滚后重启 | `candidates=3 archived=0 removed=3 left=0`：数据再次退出，归档表不重复写入 |

## 结论与边界

- 归档、清理、标记在同一 `BEGIN IMMEDIATE` 事务内；回滚与标记撤销也在同一事务。
- 回滚后重跑走 `dup` 分支：`archived=0` 而 `removed=3` 是正确结果，事务内自校验
  `removed == archived + dup` 通过，曾因把 `dup` 统计放在 `DELETE` 之后误报，已修正。
- 未覆盖：进程在事务提交瞬间被 kill 的场景，由 SQLite 原子提交保证；注入失败用例已由
  单测 `TestArchiveLegacyRegistryRollsBack` / `TestRunStepRollback` 覆盖。
- 生产库当前 `family='registry'` 为 0 行，升级到 3.5.3 时该迁移实际是空操作（0/0/0）。
