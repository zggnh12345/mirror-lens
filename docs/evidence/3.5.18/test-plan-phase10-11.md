## 2. 网络拓扑与 Registry 位置

- 验收网络：新建 bridge 网络 `ml318-acc`，仅临时容器加入。
- 真实 Registry：自建 `registry:2` 容器两个实例（reg-a、reg-b），经容器网络访问，走真实 Distribution API、真实磁盘 IO——非模拟 HTTP 响应。
- 候选/基线镜像：同一份配置、同一数据集，分别启动，避免并行互相干扰。
- 端口发布：不在 hermes 回环，统一用 `docker exec` 或同网络 sidecar `wget` 访问（见 skill harness 第2节）。

## 3. 数据集与缓存状态

- 数据集：预推送若干 manifest + 多层 blob 到 reg-a/reg-b（如 library/alpine 多个 tag，多架构/多层）。
- 每次功能请求换 fresh tag，避免缓存命中假象（skill harness 第5节）。
- 缓存状态分组：冷缓存（首次请求）与热缓存（二次请求）分别测。
- 数据集大小、tag 清单在实测前写入证据目录 `dataset.txt`。

## 4. 并发与轮数

- 功能验收（阶段10）：串行 + 小并发（并发数 1 / 4 / 8 三档）覆盖。
- 性能对照（阶段11）：固定并发数（建议 8，写死在计划里），每组 10 轮正式样本。
- 阈值探索的 5 轮数据只用于定线、不计入正式样本；阈值本就沿用 1.6 冻结值，无需重新探索。

## 5. 统计方法 / 异常值

- 指标：P50/P95/P99 TTFB、Manifest 完整响应、吞吐、错误率、额外上游请求数、胜者分布、CPU/内存/Goroutine/Lease。
- P95 插值：相邻秩线性插值（与 1.6 §12.3.0 一致）。
- 异常值：记录但不剔除，除非有确凿外部干扰证据并事先说明；不事后改阈值迁就结果。

## 6. 预先冻结的验收阈值（继承 1.6，不得改）

- A10 P95 门禁：同一固定环境、基线与竞速配对对照，竞速组 P95 TTFB 相对基线组改善 ≥ 50%，即 (基线P95 − 竞速P95)/基线P95 ≥ 0.50。
