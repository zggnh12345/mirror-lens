# 阶段11 A10 性能配对 — P0 修复后正式重测（2026-11-21）

## 为什么要重测

修复前 A10 NOT_MET 有两个独立原因：
1. P0 状态 bug：竞速预算不足后错误回退官方源，20/80 返回 401（口径不一致，§12.5）。
2. 性能本身是否达标未知——因为口径不一致，无法做有效的 OFF/ON 判定。

commit `f22a50a` 修复了 P0（`errRaceNoBudget` 时回滚 `tried`，回退到镜像源而非官方）。
修复后竞速组 0 官方回退、口径与基线一致，才首次具备有效性能判定的条件。本轮即该判定。

## 判定（保守、诚实）

1. **P0 修复效果稳定**：两次配对竞速组均 0 错误、0 官方 401，口径一致（§12.5 满足）。
   修复前同场景 20/80 官方 401 → 修复后 0/80。这是确定性的、可复现的改善。
   `budget_skipped=20`/`fallback=20` 仍在，但全部回退到镜像源，不再回退官方。

2. **P95 性能收益在阈值边缘、不稳定**：R1=52.84%（达标），R2=49.77%（未达标），
   两次仅差 3 个百分点，跨过 50% 门禁线。按 §12.3.0「达标只按 P95」，
   单次 R1 可判 PASS，但 R2 证伪了稳定性——**不能宣称稳定达标**。
   保守判定：**P0 已修复；A10 性能 PASS 不成立（NOT_MET，边缘波动）**。

3. **不挑最优样本**：R1 的 PASS 不被用来掩盖 R2 的 NOT_MET。两次都如实归档。
   不因接近阈值就事后调参（race_after_ms、延迟注入、预算均未动）。

4. **机理**：竞速把大部分尾延迟请求压到 ~200ms（R1 竞速组 P95=203ms，仅 3 个样本
   >390ms 未被 hedge 救到）；基线约 20% 请求命中 300ms 尾延迟抬高 P95 到 ~430ms。
   P95 收益大小取决于尾延迟命中与 hedge 抢跑的时序，存在天然抖动。
