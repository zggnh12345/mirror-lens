# G6 性能对照方法（3.5.25）

## 环境
- 两版同镜像 `golang:1.27.3`（Go 1.27.3 linux/amd64）、同宿主硬件（12th Gen i3-12300T）、同工作负载。
- 3.5.24 代码树：`ml3525-g0-base` 容器（基线 archive，commit=84b013d…）。
- 3.5.25 代码树：`ml3525-int-build` 容器（commit=0caf9da…）。
- 差异仅在源码，Go 编译器、GOARCH、GC 默认参数一致。

## 采集
- 现成 store benchmark：`go test ./internal/store/ -run '^$' -bench '…' -benchtime=100x -count=5 -benchmem`。
- 针对性基准：`BenchmarkAddSourceHostG6`（同 DB 循环，排除建库开销）注入两版容器各自运行。
- 每场景 5 轮独立测量，每轮 100 次操作；P50/P95 基于全部样本（非对 5 轮结果再算 P95）。

## 门槛
- §17.3 新回归门槛：P50 增幅 ≤10%、P95 增幅 ≤15%。
- 缓存性能门槛（热 P95≤2ms、冷比值≤1.5、并发成功率100%）仅适用于 gateway 缓存路径；本地隔离基准不覆盖该路径（本地段标 NOT_RUN），由下方「真实环境补充」的独立采集覆盖。

## 真实环境补充（见 g6-real/）

本地隔离基准之后，另在隔离验收实例上以真实公网源站回源、同一 IP 槽位交替换镜像，完成热缓存/冷缓存/并发 Pull 的真实环境对照，8 项门禁全 PASS（详见 `g6-real/README.md` 与 `g6-real/result.json`）。该补充不复用本地 benchmark 数字，是独立采集。

## 边界（诚实声明）
- 真实环境对照使用隔离验收实例 + 真实公网源站，**非生产实例压测**；生产未触碰、未切换。
- §17.4 的 Source API/数据库/TLS/UI 逐项延迟分解由 G4 全量测试与本目录本地 benchmark 覆盖；g6-real 聚焦缓存热/冷与并发路径。
- 不通过关闭 TLS 验证、缩短安全检查或减少真实内容验证换取速度；两版关闭应用限流仅用于消除 429 对延迟样本的污染，且两版一致（规范化有效配置，符合 §17.1）。
