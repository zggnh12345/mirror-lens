## 一、需求

3.5.22 §4.8 已定位一条客户端失败路径：`range_cap=0` 的 200-only 源（生产为 638 Source-Beta）
仍参与 `peerMedianBps`，其历史高速样本抬高同伴门槛，把合格的 206 源挤成 `speed_rejected`；
随后该源自身接管并返回 HTTP 200（忽略 Range 从 0 重发），旧源 Body 已关闭、无回退，
5s 回放预算只能送回约 3.7MB（期望 64,396,988 字节，实得 3,714,854），客户端按长度不符失败。

3.5.23 的目标是在**候选集合阶段**把不具备 Range 能力的源排除，并让 `switchAcceptable`
对 HTTP 200 直接拒绝作兜底，从根上消除这条路径。这是**资格收紧层**，与 3.5.22 的
门槛/性能层互补，不回滚 3.5.22 的 `T_i=max(F,P_i/1.3,C×1.2)` 等算法。

范围外（冻结文档 §五）：`stream.go` 核心状态机重构、扩大 5s 回放预算、旧源 Body 回退、
初始源/普通故障转移改造、性能算法与 `P_i/1.3` 系数重写、生产配置变更与部署。

## 六、勘误：冻结文档 §四「无需迁移」登记

冻结文档 `:105-108` 登记：15 处 `Preferred` 候选中 12 处经过滤（firstbyte 6 /
switch_dynamic 5 / switch_flow 1），另 3 处（`exp_switch_gate_test.go`、
`single_source_test.go`、`stream_switch_test.go`）理由是“**测试体内未直接调用换源函数**”，
登记“无需迁移”。本轮以代码调用链逐字取证，该理由的准确性如下：

- **计数本身正确**：15 / 12 / 3 的分账无误。工作区 `RangeCap:1` 实测计数：
  firstbyte 6、switch_dynamic 4、switch_flow 1、stream_switch 1、switch_eligibility_test 3；
  `watch_switch` / `exp_switch_gate` / `single_source` 为 0。
  switch_dynamic 的“5 处经过滤”中，`:54` 是 `cur`（当前源，语义上无需 RangeCap），
  实际补 `RC:1` 的是 4 处候选（`:55/:56/:112/:113`）——与冻结计数一致，易误读，特此说明。

- **登记理由对两处不成立（误登记）**：
  - `exp_switch_gate_test.go`：`f.run()`（`:100-165`）直接调用 `g.streamBody` →
    `onSlow`（`stream.go` 约 `:680`）→ `trySwitchWithSpeed`（`stream.go:694`）→
    `switchCandidates`（`watch.go:405`），**确实到达过滤路径**。“未直接调用换源函数”的
    登记事实错误。
  - `stream_switch_test.go`：`swFixture.stream()`（`:155-190`）同样调用 `g.streamBody`
    进入同一链路，**也到达过滤路径**；登记理由同样不成立。但其 fast 候选已迁 `RC:1`，
    测试语义正确，故仅理由错误、无行为缺陷。

- **登记理由对一处成立（登记正确）**：`single_source_test.go` 的
  `TestMidFillSingleSourceRepeat`（`:23`）直接调用 `g.midFill`（中途并行），不经
  `switchCandidates`（生产调用点仅 `watch.go:265/:405`），“无需迁移”结论正确。

- **附加影响（实验失真，已修复）**：`exp_switch_gate_test.go` 的三个实验——
  Exp1（`:167` 当前慢/候选快）、Exp2（`:175` 当前快/候选慢）、Exp3（`:182` 候选低于门槛）——
  其 `cand` 候选（ID2，Preferred，无 `RangeCap`）在新过滤（`:328`）下会被排除，
  `trySwitch` 返回 `ok=false`。修复前实测：Exp1/Exp2/Exp3 三者全为 `换源=false`，
  但实验仅 `t.Logf("EXP…→ 换源=%v")`、无任何断言，故门禁整体仍 `ok`、CI 静默通过——
  测试绿不代表实验观测有效。
  **修复（本版已完成，纯测试改动、不碰生产过滤）**：① 给 cand 候选补 `RangeCap:1`
  （资格门与门槛算法正交，此声明只用于隔离门槛变量）；② 三个实验补断言，EXP1 断言
  `switched==true`、EXP2/EXP3 断言 `switched==false`；③ 文件头注明隔离意图与
  EXP2 旧注释（"true 表示误换更慢源"）已过时——3.5.22 动态门槛 `C×1.2` 已使
  "当前快于候选"正确拒绝误换。修复后实测：EXP1→true、EXP2→false、EXP3→false，
  `-count=3` 三轮全稳，全量 `go vet ./...` + `go test ./...` 仍全绿（gateway 116.088s，落盘为准）。
  冻结文档 §四 :108 的登记理由仍为错误，本勘误记录不修改冻结正文。

本勘误只写入本验收文档，不修改冻结文档正文，以保持冻结基线的原貌与可追溯性。
