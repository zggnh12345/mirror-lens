## 复核修正（第二轮）

- 管理员删除 Host 后，常规探测不再用 `SetCapsLive` 复活 docker/ghcr 行；只更新已存在的 caps 行。
- `SetRepoHost` 切换 Host 时清掉新 Host 也可能继承的旧 scoped 健康/恢复状态；若新 Host 无法生成策略，整笔事务失败，不留下不可调度的半成品。
- `ResetSourceHostVerdict` / `RemoveSourceHost` 校验 Source 与 caps 行；重置会清 scoped 失败，`ResetHostCaps` 会把 recovery 置为立即到期，避免代表性仓库变化后等满 TTL。
- Realm 策略变更会失效旧能力结论并清 scoped 失败；探测写回新增 `policy_gen` CAS，探测期间策略变化的结果按 stale 丢弃。
- `SetSourceHostEnabled` 启用时重置 recovery/健康，停用后的迟到探测被拒绝；`AddSourceHost` 重新启用并重置旧状态。
- `AddSource` 为 Docker/GHCR/Foreign 每个 caps 行都建策略；`SetRealmPolicy` 可为 policy-gap 行重新启用。
- API：不存在的 Source 返回 404；缺失 Host 的删除/启停/重置返回 404；策略修改/删除后失效调度缓存。
- 迁移报告在回填后重新统计 caps/policy 行数，不再把 194 行误报成 40 行；旧库 `repo_host` 校验读源库，迁移时规范化 Host。
- 独立审查补漏：归档→恢复时清空全部 caps 结论、scoped/协议健康与 recovery，避免 Foreign Host 带着归档前证据直接回池；`SetCapsLive` 跳过 enabled=0 和已删除的 Host；`ApplyCredChanges`/CredStore 拒绝 docker.io/ghcr.io 代次；迁移 policy gap 置 enabled=0。
- 旧面板诊断恢复：`attachSourceCaps` 从 caps/recovery 派生 `registry_probe_at/error`；Host API 返回 `probe_at`。
- `CleanupArchived` 在同一事务内重新确认 archived，避免读后删误删刚恢复的源。
- API 新增源时先校验 Host，非法 Host 返回 400；Host 子路径按段匹配，避免 `hostsfoo` 被劫持。
- 候选查询的样本/速度改为批量聚合，候选路径固定为 base + trust + checks + proxy 四次查询（legacy 回退时多一次），不再按源 N+1；新增 `TestSampleStatsBatchMatchesPerSource` 校验批量与逐源结果一致。
- 性能实测（300 源，100 轮）：registry 候选约 P50 1.9ms / P95 2.7ms / P99 3.0ms；docker 候选约 P50 1.5ms / P95 3.1ms / P99 5.0ms；全部 300 候选，错误 0。`BenchmarkRegistryCandidates300` 1.87ms/op，旧逐源取样 21.15ms/op，约 11.3×。
- 浏览器 UI 已用 Playwright + Chromium 实测：登录、新增源、Host 能力块、重置、停用/启用、移除、404/非法 Host 错误、390px 无横向溢出；结果见 `docs/evidence/3.5.14-ui-acceptance-20261116.json`。
- GitLab/ECR 已完成产品级 `ProbeRegistryHost`、实际 `HostProbeRunner` 调度、应用 `/v2/` 代理回源和 Digest 对照，均记 `REAL_PASS`；证据 `docs/evidence/3.5.14-live-hostprobe-20261116.json` / `.md`。
- 低风险竞态收尾：`SetCapsLive` 携带 `policy_gen` 快照，策略变更/重置后旧探测不覆盖 Unknown；`ResetHostCaps` / `ResetSourceHostVerdict` / 启用 Host 都递增 `policy_gen` 作为 probe epoch，重置前启动的探测提交会 stale。
