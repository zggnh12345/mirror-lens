## 3. 实施顺序（依赖图）

阶段 1 — 基础设施
- RequestScope 容器（生命周期、账本注册、父 Context 取消传播）。
- R（16）与 P（8192）两阶段门控；P 计量点包裹 t.base，Token 请求统一走包装（解决 t.base 绕行）。
- G 容量与 N 内部准入（limits.enabled=false 时仍用 GlobalConcurrency）。
- P 耗尽处理落地：未发响应头回 503 + no-store + REQUEST_BUDGET_EXHAUSTED；已发正文取消 Attempt/关 Body/不提交缓存/清理部分文件；不污染 Source 样本。
- GlobalLeasePool 封装现有 scheduler.Lease；Preflight 独立 preSem。
- 门禁：T52/T57/T60。

阶段 2 — 核心状态机
- Identity Claim（三态）与 Chain（Closing 拒注册）。
- Attempt（四态）、send-commit 边界、Body 幂等关闭、Lease 释放。
- 门禁：T50/T51/T53/T56。

阶段 3 — 跨站与身份
- Authority 唯一 Attempt（软比对与兜底复用一次结果）。
- B Digest 投票状态机（200ms、正文已校验、不同逻辑 Registry + 不同 source_id、窗口外丢弃）。
- 结果账本 AttemptResult[] 与全 Miss 仲裁（统一账本、分 Chain 归属、错误优先级、P 耗尽独立通道）。
- 门禁：T63、B02/B06、全 Miss 仲裁新增用例。

阶段 4 — 路径接入
- A 站内竞速适配（共享 Claim，复用 registryrace.go 能力）。
- B 跨 Registry 竞速 + 顺序补位 + M/C/A。
- fb 静态抑制快照前置；Hedge 三指标拆分并接 P；Midfill 一轮 Preflight 共享 + RangeWorkCap=1024 + 每 Range≤4 目标。
- RegistryRetryToken（B16）、A/B 部署期全局回退（单请求不混新旧）。
- 门禁：T54/T55/T59/T61/T62、B04/B05/B07/B08/B16/B18。

阶段 5 — Schema 与迁移（最后，依赖阶段 1–4 的准入语义）
- 新建 trusted_source_mappings / trusted_mapping_generation / trusted_mapping_audit。
- 提升 schema Version、重算 hash、写 schema_meta；迁移工具扩展与 Generation 回填。
- 管理 API（GET/POST/PUT/DELETE /api/trusted-mappings），同事务审计。
- 门禁：T58、迁移/回滚演练。

阶段 6 — 测试与验收
- 全量回归、独立复核、实机与性能验收、清理。

## 6. 实机与性能验收

- 用隔离测试数据库与测试 Registry；基线与候选同环境至少 5 组配对。
- 报告：中位数、P95、吞吐、CPU、内存、错误率、内容 Digest 一致性。
- 门槛见 test-matrix §5；未涉及路径中位吞吐≥基线 95%，已优化路径≥5 组可复现提升，资源消耗恶化≤10%。
- 无稳定外部真实 Registry 时，用可控测试 Registry 完成确定性测试，真实外网性能标记外部环境限制，不伪报全部实机通过。
