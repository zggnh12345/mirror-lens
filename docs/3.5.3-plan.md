   归档行数 = 删除行数、标记唯一、`source_health` 无 registry 残留；再跑一次确认幂等；
   最后用 `UnarchiveLegacyRegistry` 验证补回与冲突跳过。产出演练记录进本文件。
2. **Phase B 观测**：启动日志输出 `archived/removed/already_done`；异常（标记在但仍有行）
   已经报错，需确认这条路径不会让服务起不来——当前是 fail-fast，需在发布说明写明。
3. **P2-3 修复**：`Reclaim` 对 `StateReclaiming` 早退，避免同一 Lease 重复计入
   `LeaseReclaim` 指标和 `ReclaimSource` 返回数。**调用方审计已完成**：生产代码里
   `ReclaimSource` 无调用方（仅测试断言 `n == 1`），`l.Reclaim` 只有网关 stall 看门狗；
   早退不影响现有断言。改动仍按规矩先说明再动手。
4. **C0 裁定**：等你对 C0-1/2/3 给结论。若选「C 单租户共享缓存 + 不解析 + 不引入 HMAC」，
   落地只有一条前置保护：将来若新增上游 registry 凭据配置，启动时必须拒绝或显式放行；
   当前代码没有该配置项，实际工作量接近零。

## P1：优化（不阻塞发布）

| 项 | 现状 | 优化方向 | 风险 |
| --- | --- | --- | --- |
| 升级重探窗口 | A1 fail-closed，升级后 `registry_cap=1` 的 Host 全部进 `initial`，候选短暂为空 | 评估「探测预热」：升级后首轮扫描提高并发或优先探测有流量的 Host | 不能改变 fail-closed 语义；只调顺序与并发，不预置健康结论 |
| `repo_host=''` 兼容 | 3.5.0 建列的默认值，被当作 Docker Hub，不进 Host 恢复/探测 | 增加显式 `repo_host` 归一化或回填迁移，并在 UI 标出「未识别」 | 改归类会影响候选集合，需先出影响面清单 |
| 种子标记时机 | 一次性标记检查在 `BEGIN IMMEDIATE` 之前 | 移入事务内，为多实例做准备 | 单 Runner 下无行为变化，改动小但需并发用例 |
| 多实例 gen guard | 当前 gen guard 不能跨实例复用 | 设计代次所有权（实例 ID + 租约），解除单 Runner 限制 | 大改，需单独立项与设计评审 |
