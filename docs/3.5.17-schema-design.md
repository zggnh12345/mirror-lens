# 3.5.17 Schema 设计（冻结输入）

> 本文件给出 AUD-04-2 显式可信映射的 DDL、约束、有效期、Generation、审计与管理 API。
> 基线：d1ea272；当前 canonical schema Version=3.5.14（schema.go:19），24 张表。
> 建议 DDL 不是现有数据库结构。17b 新建；生产迁移须单独授权。

## 1. 设计裁定（AUD-04-2）

- 运行时映射表只保存当前配置；完整历史进独立追加式审计表。
- 一对多：(registry_host, source_id) 一个 Host 多个可信 Source。
- 永久有效用 0；到期不删除，只不参与选择。
- Generation 每规范化 Registry Host 独立递增；任何变更同事务递增。
- Source 删除时映射随外键 CASCADE 删除，审计历史保留。
- 内容缓存身份不变：映射/排序变化不得改 CacheKey 或内容 SHA，避免把不同内容身份混为一体。

## 2. DDL（建议）

```sql
CREATE TABLE trusted_source_mappings (
    registry_host TEXT NOT NULL,
    source_id INTEGER NOT NULL,
    priority INTEGER NOT NULL DEFAULT 100,
    valid_from INTEGER NOT NULL DEFAULT 0,
    valid_until INTEGER NOT NULL DEFAULT 0,
    enabled INTEGER NOT NULL DEFAULT 1,
    PRIMARY KEY (registry_host, source_id),
    CHECK (priority >= 0),
    CHECK (enabled IN (0, 1)),
    CHECK (
        valid_until = 0
        OR valid_from = 0
        OR valid_until > valid_from
    ),
    FOREIGN KEY (source_id)
        REFERENCES sources(id)
        ON DELETE CASCADE
);

CREATE INDEX idx_trusted_source_mappings_lookup
ON trusted_source_mappings (
    registry_host,
    enabled,
    priority,
    source_id
);

CREATE TABLE trusted_mapping_generation (
    registry_host TEXT PRIMARY KEY,
    generation INTEGER NOT NULL DEFAULT 1,
    CHECK (generation >= 1)
);

CREATE TABLE trusted_mapping_audit (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    registry_host TEXT NOT NULL,
    source_id INTEGER NOT NULL,
    operation TEXT NOT NULL,
    old_snapshot TEXT,
    new_snapshot TEXT,
    actor TEXT NOT NULL,
    created_at INTEGER NOT NULL
);
```

- source_realm_policy（:64-76）：policy_gen 单调代次。
- source_events（:167-177）：结果事件。
- audit（:275-283）：管理审计字段 ts/ip/user/action/target/detail/ok。

## 3. 四项明确规则

### 3.1 有效期
- valid_from=0：立即生效。
- valid_until=0：永久有效。
- 仅当当前时间 t 满足 (valid_from=0 或 t>=valid_from) 且 (valid_until=0 或 t<valid_until) 时参与候选。
- 到期不删除记录；查询按有效期过滤。

### 3.2 删除与暂停
- 暂停使用：enabled=0（仍保留行与历史）。
- 管理员删除：运行时映射表硬删除该行。
- 删除前后快照必须写入 trusted_mapping_audit。
- Source 删除：ON DELETE CASCADE 清映射行，审计表无外键引用 source_id，历史保留。

### 3.3 Generation
- 每规范化 registry_host 一行，generation 初始 1。
- 映射创建/修改/暂停/恢复/删除：同一事务内 `generation = generation + 1`，并写审计快照。
- RequestScope 开始时读取固定 Generation 与候选快照；请求执行中 Generation 变化不改变本 Scope 候选集合。
- Generation 变化使映射选择快照失效，不改内容缓存身份。

### 3.4 缓存
- 映射变化 → 使"候选选择快照"失效（下一请求重取 Generation/候选）。
- 不改 CacheKey、不改内容 SHA、不把不同内容身份合并。
- 内容身份仍由规范化 Registry、Repository、Manifest Identity 决定。

## 4. 管理 API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /api/trusted-mappings | 查询映射（可按 registry_host 过滤） |
| POST | /api/trusted-mappings | 新建映射 |
| PUT | /api/trusted-mappings | 修改映射 |
| DELETE | /api/trusted-mappings | 删除映射 |

- 全部沿用现有管理员认证与 CSRF 中间件（api.go:232-240 `guard(csrf(...))` 模式）。
- 输入校验：registry_host 规范化、source_id 存在、priority≥0、valid_until>valid_from 或为 0、唯一约束冲突返回明确错误。
- 事务：映射变更 + Generation 递增 + 审计快照必须在同一数据库事务提交。
- 审计耐久：必须同事务写 trusted_mapping_audit；不得仅用异步 Store.Audit（audit.go:96 drain）作唯一机制。可参照凭据写路径的同事务审计（credwrite.go:114）。
- 错误语义：400 校验失败 / 409 唯一冲突 / 404 不存在 / 401/403 未登录或无 CSRF。

## 5. 迁移要求

- 新增表属 Schema 变更：须提升 schema Version（如 3.5.15），重算 CanonicalSchemaHash，写 schema_meta 单行。
- 迁移工具按现有离线迁移骨架（3.5.7→3.5.11）扩展；新表 copyAll 后回填 Generation（每个已配置 Host 一行 generation=1）。
- 迁移失败保留窗口、回滚边界与审计记录须在 implementation-plan 的 Schema 阶段定义；生产执行单独授权，17b 只在隔离库演练。
- 不修改现有 24 张表语义；trusted_source_mappings 与 trusted_mapping_generation、trusted_mapping_audit 为纯新增。

## 6. 与其他冻结项的关系

- F08 显式映射模型：本 DDL 即 F08 落地；B 投票的"不同 Source"判定读 source_id。
- F19：Generation 快照在 RequestScope 开始时固定，供 Claim 前的资格判定与静态抑制快照使用。
- R/P/G：映射只影响候选准入，不改预算公式。
- AUD-04-3：投票要求不同 source_id，与映射的一对多结构一致。
- 缓存：映射变化不改内容身份（见 3.4）。

## 7. 测试要求

- T58：SQLite 多连接并发写映射，断言约束生效、无 database is locked。
- 一对一/一对多插入、唯一约束、priority 排序、有效期边界（valid_from=0/valid_until=0/区间内/到期）。
- Generation：每次变更递增、并发变更最终一致、Scope 快照不受中途变更影响。
- 审计：删除前后快照入表、Source 级联删除后审计保留、同事务提交（崩溃/失败不产生半写）。
- API：未登录/无 CSRF 拒绝、校验失败/冲突/不存在的错误码。
- 缓存身份：映射变化后 CacheKey 与内容 SHA 不变。
