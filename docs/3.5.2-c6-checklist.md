## C6.0 边界

**做：** 把「`cap=1` 且成功结论已超 TTL」的行从投影态 `ok` 物化为 `expired`，并保证它被重新探测；验证 `expired → ok / failed` 的完整闭环。

**不做：**
- 不修改候选 SQL。C5 的 `last_success_at >= now - TTL` 闸门已经阻止过期结论进候选，C6 只是让持久化投影追上事实。
- 不修改 `DeriveState` 的六态定义、优先级与语义。
- 不修改 `ListDueHostProbes` 的筛选条件与 C4 的扫描模型（30s 节拍 + 单 Runner）。
- 不修改 `CommitHostProbe` 的成功 / 失败提交语义。
- 不引入 `recheck_requested` 列、不引入进程内队列、不新增 ticker、不在 API 读路径写库。
- 不支持多 Runner / 多实例，不做种子迁移（独立决策）。

## C6.1 现状核对（避免重复造）

| 事实 | 位置 | 对 C6 的含义 |

结论：C6 不是新增状态机，而是**补一个「无新探测时也推进投影」的物化入口**，并验证闭环。

## C6.2 物化入口

新增 `internal/store/recovery_expire.go`：

```go
// MaterializeExpired 把已超 TTL 的 ok 行推进为 expired，并把 next_probe_at
// 拉到传入的 now，使其在下一轮扫描被重新探测。返回实际成功物化的行数。
func (s *Store) MaterializeExpired(now time.Time) (int, error)
```

实现约束（验收标准）：

| 项目 | 要求 |
| --- | --- |
| 事务 | 单事务，`BEGIN IMMEDIATE`（与 `CommitHostProbe` 相同的并发控制方式） |
| 时间 | 统一使用调用方传入的 `now`；Store 内部不再取当前时间（TTL 只从 `s.RecoveryTTL()` 读） |
| 候选 | `family='registry' AND state='ok' AND sources.registry_cap=1 AND sources.status<>'archived' AND last_success_at>0 AND last_success_at < now-TTL` |
| 代次 | 事务内读 `registry_host_gen.gen`（缺行按 0）与 `source_health_scope(gen=当前 gen)`；代次不等的行派生结果必然不是 `expired`，跳过 |
| 派生 | 每行调用 `DeriveState` 复算，**不得仅凭 SQL 候选条件直接 UPDATE** |
| 更新 | 仅允许 `ok → expired`；其余派生结果一律跳过，不做通用状态修复 |
| CAS | `WHERE source_id=? AND family='registry' AND scope=? AND state='ok' AND last_success_at=? AND gen=?` |
| 调度 | 成功时 `next_probe_at = now` |
| 幂等 | 重复执行不产生额外状态变化；CAS 影响 0 行视为并发状态已变，不强行覆盖 |
| 结果 | 返回实际成功物化数量与错误 |

要点：

1. **CAS 必须含 `gen`**：凭据代次可能在物化期间变化；即使 `last_success_at` 未变，也不允许旧代次的物化结果写入新代次行。
2. cutoff 与 C5 完全同源：`now.Unix() - int64(s.RecoveryTTL()/time.Second)`，边界 `last_success_at < cutoff`（取等仍 `ok`）。
3. 派生需要三份证据：`sources.registry_cap`、`registry_host_gen.gen`、`source_health_scope(gen=当前 gen)`；缺 scoped 行时 `HasScoped=false`，派生为 `initial`，自然跳过。
4. 候选 SQL 只做廉价粗选；"当前代次有效"由事务内派生复核 + CAS 的 `gen` 双重保证，不依赖调用顺序。
5. 观测：实际推进行数累加到 `recovery_expired_materialized_total`（`internal/metrics`）。

## C6.3 调度衔接

`HostProbeRunner.Once` 内的固定执行顺序（不得调换）：

1. 获取本轮统一的 `now`（`o.Now()` 一次）。
2. `st.MaterializeExpired(now)`。
3. 物化失败 → `log.Printf` 记录错误，继续本轮探测（下一轮重试）；不得静默当作成功，也不得因此中止扫描。
4. `ListDueHostProbes(now)` 使用同一个 `now`。
5. 按现有流程执行探测。

其余约束：
- 物化把 `next_probe_at` 置 `now`，同一轮即可被选中；本轮已过扫描则最迟下一轮 30s 后重探。
- 不新增 ticker、API 惰性物化或唤醒通道；持久化状态仍是唯一权威。
- 不改 C4 的 `next_probe_at` 调度语义。

## C6.4 TTL 配置变更

| 变更 | 行为 |
| --- | --- |
| 缩短 TTL | 候选立即收紧（C5 SQL 实时判断）；下一轮物化把已过期 `ok` 行转为 `expired` 并把 `next_probe_at` 拉到 `now`，无需批量迁移脚本 |
| 延长 TTL | 已 `expired` 的行**不自动**回到 `ok`；必须重验成功写回，避免"改配置即放行未经重验的旧结论" |
| 修改 TTL 不改历史时间戳 | 只影响判定与调度，不重写 `last_success_at` |

## C6.5 测试矩阵

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 恰好 `now-last_success == TTL` | 不物化，仍 `ok` |
| 2 | 超过 TTL（`+1s`） | `ok → expired`，`next_probe_at=now` |
| 3 | 同一记录重复物化 | 第二次推进 0 行，状态不变 |
| 4 | 先行状态变化保护：物化前已提交新的成功探测 | 推进 0 行；新 `ok` 与 `last_success_at` 不被覆盖（**不是**事务内并发竞争复现） |
| 5 | 先行状态变化保护：物化前代次已推进 | 旧代次行不物化；当前代次派生为 `initial`（**不是**事务内并发竞争复现） |
| 6 | 物化后 `ListDueHostProbes` | 该源在列（`next_probe_at=now`） |
| 7 | 物化后 Registry 候选 | 仍为 0（与 C5 闸门一致） |
| 8 | 端到端：`ok → expired → 探测成功` | `expired → ok`，`next_probe_at=now+TTL` |
| 9 | 端到端：`ok → expired → 探测失败` | 按现有派生进 `failed`，`rec_failures=1`，退避生效，候选仍 0 |
| 10 | TTL 缩短 | 下一轮物化拉近重探时间 |
| 11 | TTL 延长 | 已物化的 `expired` 不自动恢复 |
| 12 | 重启后 | 状态与调度时间保持一致，不依赖内存 |

#4、#5 验证的是「状态变化先于物化时，物化不得覆盖新事实」，命名统一为**先行状态变化保护测试**；`BEGIN IMMEDIATE` 已把事务内的竞争写者排除，不得把它们标成真实并发竞争测试。

## C6-E 存量 Recovery 显式物化（新方案，代码待验收）

定位：**一次性 Recovery 显式物化与 cap 状态固化**。不再承诺候选连续性，也不承诺保留历史健康状态。

### 信息边界（为什么不迁移历史状态）

3.5.1 及以前的 `source_health_scope` 行在 `migrateScopedGen` 里统一补成 `gen=0`（`migrate_recovery.go:120`）。3.5.2 的无凭据探测也会写 `gen=0`（`commit.go:150-155`），两者落在同一整数空间，无法区分。同时：

- `registry_host_gen` 在 3.5.1 库里是空表，没有任何回填；
- 迁移在 `store.Open` 内执行（`store.go:411`），凭据对账在 `main.go:339` 之后；
- 因此种子执行时不存在任何可证明的当前代次记录。

结论：不能把无法证明代次归属的历史 `fails` / `ok_at` 恢复成 `failed` / `ok` / `expired`。宁可首次升级后重探。

### 状态映射

| cap | 种子状态 | next_probe_at |
| --- | --- | --- |
| 2 | `hard-excluded` | 0（沿用现有排除语义） |
| 0 | `unsupported` | `now + 6h`（沿用既有周期重验，不改 `ListDueHostProbes`） |
| 其他（含 1 / -1） | `initial` | `now` |

### 一次性机制

- 标记：`meta` 表 `recovery_seed_v1 = 1`；标记存在则整体跳过。
- 种子 INSERT 与标记写入同一 `BEGIN IMMEDIATE` 事务，`ON CONFLICT DO NOTHING`。
- 事务失败全部回滚，启动 fail-fast；成功后手动删除的行不会补回。
- `meta` 的幂等 DDL 已从 `migrateAccel` 提前到基础 schema，执行顺序：基础 schema → recovery schema 迁移 → 一次性 seed。
- 不读 `source_health_scope`，不改 `source_health`，不改 `DeriveState` / `CommitHostProbe`，不新增状态。
- 范围：`status<>'archived' AND repo_host<>'' AND repo_host<>'ghcr.io'`，不过滤 `enabled`；已有 recovery 行不覆盖。
- `scope` 直接取 `sources.repo_host`，不做二次规范化：3.5.0 起 `repo_host` 的写入路径只有 `AddSource`、`ApplyCredChanges`、历史还原，三处都经 `registryhost.Check`（小写、去空格、去尾点）。`TestSeedRecoveryScopeEqualsNormalizedRepoHost` 钉住这条不变量。
