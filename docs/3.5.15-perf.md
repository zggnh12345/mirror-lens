# 3.5.15 性能实测（P01–P05）

日期：2026-11-17
代码：`/opt/data/cache/scratch/ml8`（3.5.15 未提交改动）
基线：`v3.5.14`（`6e07752`，独立 worktree 构建）
环境：本机 Docker，`ml315real` bridge（172.31.241.0/24）；`registry:2` 2.8.3；独立测试 CA；无生产流量

## 0. 口径与阈值

- 本轮在汇总结果前固定验收阈值：本地 fixture 的 P95 ≤ 50 ms，错误率 = 0；未达到即不记为 PASS。
- 所有延迟为客户端端到端时间，包含应用进程、回源、TLS/认证；不含测试容器启动时间。
- P01 的“匿名路径”两边都使用 `auth.require_token=false`，避免把 Access Token 校验差异算进缓存路径。
- P02 的 Basic/Bearer 分开统计；Bearer 先预热 Token Cache，再测命中路径。
- P03 是 50 个 Host 的 `ListStatus` 成本；产品凭据 allowlist 仍只有 `quay.io`/`gcr.io`，因此这是**存储层 50 Host fixture**，不是“产品已支持 50 个私有 Host”的声明。
- P04 的 Token 命中率用 Token 端点日志计数，不依赖应用自报指标。

## 1. P01 匿名路径 A/B（3.5.14 vs 3.5.15）

方法：同一台机器、同一匿名 registry（`registry-1.docker.io` 网络别名指向本地 `registry:2`）、同一 manifest；两边先预热，再各跑 5 轮 × 500 请求、并发 20。结果取 5 轮中位数。

| 指标 | 3.5.14 | 3.5.15 | 变化 |
|---|---:|---:|---:|
| 吞吐 RPS（中位数） | 2987.4 | 3369.8 | +12.8% |
| P50 | 4.609 ms | 3.788 ms | -17.8% |
| P95 | 19.084 ms | 18.244 ms | -4.4% |
| P99 | 30.817 ms | 24.249 ms | -21.3% |
| 平均 | 6.630 ms | 5.878 ms | -11.3% |
| 错误数 / 总请求 | 0 / 2500 | 0 / 2500 | 0 |

5 轮范围：3.5.14 P95 15.653–25.203 ms；3.5.15 P95 14.407–26.834 ms。两边都远低于 50 ms 阈值，未观察到缓存路径退化。

## 2. P02 认证路径（Basic / Bearer 分开）

方法：当前 3.5.15 应用，500 请求、并发 20；Bearer 先预热 Token Cache；Token 未命中用重启应用后的单请求测。

| 场景 | RPS | P50 | P95 | P99 | 错误 |
|---|---:|---:|---:|---:|---:|
| Basic（quay.io，Registry 直接 Basic） | 949.0 | 18.117 ms | 33.437 ms | 83.206 ms | 0 |
| Bearer（gcr.io，Token 端点 Basic，命中缓存） | 1016.6 | 16.393 ms | 34.856 ms | 78.691 ms | 0 |
| Bearer 单请求（Token 未命中） | 31.8 | 31.307 ms | 31.307 ms | 31.307 ms | 0 |
| Bearer 500 请求（Token 命中） | 1086.4 | 15.956 ms | 29.334 ms | 70.077 ms | 0 |

Bearer 命中路径与 Basic 接近；单次 Token 未命中约多 15 ms，符合一次 Token 端点往返的成本。

## 3. P03 50 Host 成本（存储层，历史数据，当前不可复现）

方法：临时 Go 程序创建独立 SQLite 库与凭据文件，分别写入 2 / 50 个 Host 代次记录，调用 `secret.Store.ListStatus()` 200 次，取分位。Host 使用 50 个合法的 Artifact Registry 形式（`locNN-docker.pkg.dev`），以通过当时的 `registryhost.Check`；不经过产品凭据 allowlist 的写入口。

> 注意：本轮已按 1.6 D.1 收紧 `credentialHost`，`*.pkg.dev` 不再进入凭据状态/列表路径。因此下表的 50 Host 数字是收紧前的历史数据，**不能作为当前代码的 P03 证据**；当前代码下 P03 记为 `NOT_EXECUTED`，除非另建不经过 `credentialHost` 的存储层测试入口，但那也不能替代产品级 50 Host 验收。

| Host 数 | P50 | P95 | P99 | 平均 |
|---:|---:|---:|---:|---:|
| 2 | 46 µs | 50 µs | 63.2 µs | 47.4 µs |
| 50 | 525 µs | 762.8 µs | 1158.6 µs | 557.3 µs |

50 Host 的 P95 约为 2 Host 的 15 倍，呈明显 O(N) 增长；与代码中 `ListStatus` 对每个 Host 重新读文件/查代次的实现一致。该结果证明 50 Host 下有可测成本，但**不能**据此宣称产品已支持 50 个私有 Host 凭据——当前 allowlist 只有两个 Host。

## 4. P04 Token Cache

| 场景 | Token 端点请求数 | 结果 |
|---|---:|---|
| 应用重启后 20 次 gcr.io manifest | 1 | 19 次命中缓存，命中率 95% |
| 预热后 500 次 gcr.io manifest | 0 新增 | 500 次全部命中，命中率 100% |
| 轮换 Token 签名密钥后 1 次请求 | 1 新增 | 旧 Token 被 Registry 401，应用刷新后 200 |

Token 端点日志同时记录了 `auth=basic` 与 `auth=none`，分别对应 `bearer_token_basic` 与 `bearer_token_none` 两种真实模式。

## 5. P05 缓存命中 vs 绕过

| 路径 | 响应头 | P95 |
|---|---|---:|
| 公共 Host 缓存命中 | `X-Ml-Cache: HIT` | 18.244 ms（P01 中位数） |
| 私有 Basic 绕过 | `X-Ml-Cache: BYPASS`、`Cache-Control: no-store, private` | 33.437 ms |
| 私有 Bearer 绕过 | `X-Ml-Cache: BYPASS`、`Cache-Control: no-store, private` | 29.334 ms |

私有路径比公共缓存命中多约 11–15 ms，主要来自一次真实回源与认证握手；这是“不缓存私有内容”的预期代价。公共路径首次 `MISS`、后续 `HIT`，未因 3.5.15 改动退化。

## 6. 结论

- P01、P02、P04、P05：本地真实 fixture 下达到预设阈值，记为 **SIMULATED_PASS（本地 fixture）**。
- P03：历史 50 Host 数字产生于 `credentialHost` 收紧前，当前代码已拒绝 `*.pkg.dev`，该数字不能作为当前 P03 证据；P03 记为 **NOT_EXECUTED（产品 allowlist 限制）**。
- 外部 `quay.io` / `gcr.io` 私有账号仍未验证，保持 **BLOCKED_EXTERNAL_SOURCE**；本报告不把本地别名 fixture 当作外部账号 REAL_PASS。
