## 兼容边界（随发布说明保留）

**首次从 3.5.1 升级到 3.5.2 时，所有 `registry_cap=1` 的 Host 都会进入 `initial`，候选暂时为空；必须等当前代次的 Host 探测成功，才重新具备候选资格。**

- 原因：3.5.1 的 scoped 行迁移后一律 `gen=0`，与无凭据探测合法写出的 `gen=0` 不可区分，按 fail-closed 不授予候选资格。
- `cap=2` → `hard-excluded`、`cap=0` → `unsupported`（6h 周期重验）不受影响。
- 不承诺候选连续性，不承诺保留历史健康状态，不回填 `registry_host_gen`。

详见 `docs/release-notes-3.5.2.md`。

## A2 范围

**已冻结设计方向，已实现待复核。** 唯一目标：Host 探测的失败退避不依赖进程内存，`next_probe_at` 成为唯一调度时间权威。

- 设计文档：`docs/3.5.2-a2-design.md`（草案 v1，含 A2-0 源码审计与 O1–O4/D1–D2 待裁定项）
- 范围：A2-0 审计（已完成）→ A2-1 持久化退避与独立 `retry_failures` 计数器 → A2-2 最小观测 → A2-3 回归验收
- 明确排除：逐 Host 定时器、多 Runner/多实例、Registry 协议与候选算法重写、六态状态机调整、Guard 重构
- 关键语义：不复用 `rec_failures` 作为退避输入；`CommitHostProbe` 成功提交后由数据库决定时间，Runner 不得覆盖
