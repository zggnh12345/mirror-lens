## 1. 现状证据

### 1.1 路由与候选

- 3.5.7 基线：`sched()` 只有在旧的 `MultiOrigin && foreign && !isGhcrHost(host)` 时才返回 `registry:<host>`；否则 `kindForHost` 返回 `docker`，且 `officialOnly(host, foreign)` 对非 GHCR foreign 返回 `true`。本版删除这个全局布尔，只保留范围列表。
- 3.5.7 基线：`MultiOrigin` 只从 `ML_REGISTRY_MULTI_ORIGIN=1` 读取，默认关闭；本版不再使用该布尔。
- `internal/adapter/registryadapter/registry.go:60-70`：`hostAllowed()` 在 `a.Hosts != nil` 时只查自定义 map，不再查全局 Host 白名单。
- `internal/gateway/registry.go:31-42`：`registryChannelOff` 只区分 `ghcr.io` 和“其余全部”，foreign Host 全部落到 `dockerOff`。
- `internal/gateway/registry.go:52-57`：`isReferrersPath` 在 `Route` 和 Host 通道检查之前直接返回 200；即使 Host 被禁用，referrers 路径也会绕过准入。
- `internal/gateway/gateway.go:514-538`：`targets()` 在 `OfficialOnly=false` 时把候选放在官方源前面；候选为空时仍保留官方源，符合 Phase 1 的回退语义。

### 1.2 Host 白名单

`internal/registryhost/registryhost.go:16-20` 的 `defaultHosts` 是 11 个精确 Host，不包含 `<location>-docker.pkg.dev`。`Allowed()` 和 `Check()` 只做精确匹配，所以：

- Source 不能写 `us-docker.pkg.dev`；
- `/v2/us-docker.pkg.dev/...` 会被当成默认上游的仓库名，而不是 Artifact Registry；
- `RegistryCandidatesRaw("us-docker.pkg.dev")` 无法进入正常的 Host 路由。

## 2. 设计决策

### D1：把“可访问”“可加速”“调度策略”拆成三层

Phase 1 明确区分三件事，不能用同一个开关代替：

| 层 | 配置/代码 | 作用 |
|---|---|---|
| 访问准入 | `registryhost.Allowed()` + `disabled_hosts` + `docker_enabled` / `ghcr_enabled` | 某个 Host 能不能被请求、能不能被回源 |
| Source 使用 | `multi_origin_hosts` | 某个 Host 是否允许进入加速 Source 调度 |
| 调度策略 | `registry:<host>` | 多源候选如何排序、健康如何隔离 |

因此：

- `disabled_hosts` 关闭的是**访问**；
- `multi_origin_hosts` 关闭的是**加速 Source**，但官方直连仍然可以存在；
- `multi_origin_hosts=[]` 只是退回旧策略，不等同于关闭 Host。

### D2：`multi_origin_hosts` 是唯一范围，不设总开关

配置：

```yaml
registry:
  multi_origin_hosts:
    - gcr.io
    - registry.k8s.io
    - "*.pkg.dev"
  disabled_hosts: []
```

语义：

- `multi_origin_hosts` 非空：只有列表中的 Host 进入 `registry:<host>`；
- `multi_origin_hosts` 为空：**没有 Host** 进入多源调度，不表示“全部”；
- 不设 `registry.multi_origin` 布尔总开关，列表就是唯一来源；
- 默认值为 `["gcr.io", "registry.k8s.io", "*.pkg.dev", "quay.io", "mcr.microsoft.com", "registry.gitlab.com", "public.ecr.aws", "cgr.dev"]`，覆盖第一批 8 个公开 Registry 匹配项；`lscr.io` 暂不启用；
- `*.pkg.dev` 是 Artifact Registry 的**受限模式**，只匹配 `registryhost.IsArtifactRegistry(host)` 认可的三段 Host，不是任意 `*.pkg.dev` 通配；
- 不在范围内的 Foreign Host（例如 `lscr.io`、尚未加入白名单的 `nvcr.io`）即使数据库里已有 Source，也不会因为它们存在而改变回源路径；仍走旧的 `docker + OfficialOnly` 行为。

为什么不再保留全局 `multi_origin`：

- 当前 `defaultHosts` 有 11 个精确 Host，另有 Artifact Registry 模式；
- 全局打开会让所有 Foreign Host 都可能进入候选池，和第一批 8 个匹配项的验收范围不一致；
- 这会改变未纳入本批的既有 Source 的实际行为，属于范围扩大。

`multi_origin_hosts` 支持两种写法：

1. 精确 Host：`gcr.io`、`registry.k8s.io`、`us-docker.pkg.dev`；
2. Artifact Registry 模式：`*.pkg.dev`，实际只匹配合法的 `<location>-docker.pkg.dev`。

`docker.io`、`registry-1.docker.io`、`ghcr.io` 不允许写入 `multi_origin_hosts`；GHCR 继续走既有 ghcr 路径。

### D3：`disabled_hosts` 仍是访问拒绝列表，默认全部启用

配置：

```yaml
registry:
  disabled_hosts:
    - registry.k8s.io
```

语义：

- 列表为空：不改变现有访问准入；
- 列表中的 Host：Manifest、Blob、HEAD、referrers、缓存命中和共享 Blob 全部返回 404；
- 只接受规范化后的精确 Host；不支持通配关闭；Artifact Registry 要逐条列出实际 Host；
- `docker.io`、`registry-1.docker.io`、`ghcr.io` 继续由 `docker_enabled` / `ghcr_enabled` 控制，禁止写入本列表，避免两套开关矛盾；
- 这个列表只控制访问，不影响 `multi_origin_hosts` 和 `registry:<host>` 的配置本身。

### D4：Artifact Registry 必须是严格 DNS Label 模式

`registryhost` 增加 Artifact Registry 判断，规则必须同时满足：

```text
Host 恰好三个 DNS Label
第三、第二段分别是 pkg、dev
第一段以 -docker 结尾
location = 第一段去掉 "-docker" 后的部分
```

`location` 必须满足：

- 长度 1–63；
- 只能包含小写字母、数字、连字符；
- 首字符和末字符必须是字母或数字；
- 不允许包含点号；
- 不允许连续 `--`；
- 不允许空 location。

测试表：

| Host | 预期 |
|---|---|
| `us-docker.pkg.dev` | 通过 |
| `europe-west1-docker.pkg.dev` | 通过 |
| `asia-northeast1-docker.pkg.dev` | 通过 |
| `foo.pkg.dev` | 拒绝 |
| `a.b-docker.pkg.dev` | 拒绝 |
| `-foo-docker.pkg.dev` | 拒绝 |
| `foo--docker.pkg.dev` | 拒绝 |
| `foo-.pkg.dev` | 拒绝 |

另外：

- `Normalize()` 继续拒绝端口、userinfo、协议、路径、IP、空标签；
- `Check()` 必须先 normalize，再按全局白名单和 Artifact Registry 模式判断；
- `Hosts()` 仍只返回 11 个精确 Host，不把模式混进状态矩阵的“11 个 Host”口径。

### D5：Host/Repo/referrers 必须来自同一套解析结果

删除 `HostForPath()` 的设计。新增一个 Adapter 内部解析结果，Gateway 和 Plan 不再各自拆路径：

```go
type ParsedPath struct {
    Kind  Kind
    Host  string // 逻辑 Host；ping 为空
    Repo  string // 原始 repo（含 Host 前缀），供 Route 兼容
    Name  string // 去掉 Host 前缀后的上游仓库名
    Ref   string // manifest tag/digest，或 blob digest
}
```

接口：

```go
func (a *Adapter) ParsePath(path string) (ParsedPath, error)
func (a *Adapter) Route(path string) (Kind, string, string, error) // 包装 ParsePath，兼容旧调用
func (a *Adapter) PlanParsed(r *http.Request, p ParsedPath) (*adapter.Plan, error)
func (a *Adapter) Plan(r *http.Request) (*adapter.Plan, error) // ParsePath + PlanParsed
```

`ParsePath` 负责：

- `/v2` / `/v2/` → `KindPing`；
- `/v2/<repo>/referrers/<digest>` → `KindReferrers`；
- `/v2/<repo>/blobs/uploads/...` → `KindWrite`；
- `/v2/<repo>/manifests/<ref>` → `KindManifest`；
- `/v2/<repo>/blobs/<digest>` → `KindBlob`；
- 统一调用 `parseRepo()` 得到 `Host`、`Repo`、`Name`；
- 统一校验 repo 和 digest。

严格 Host 解析：

```text
首段不含 "."：这是 Docker Hub 仓库名，Host = 默认上游
首段含 "." 且通过 hostAllowed：这是显式 Host，剥离前缀
首段含 "." 但不在白名单：返回 ErrUnknownHost，不能静默回落成 Docker Hub 仓库名
```

这条规则会改变现有行为：

- 当前 `TestPlanRoutesRegistryHostPrefix` 中 `evil.example.com/a/b` 被当成 Docker Hub 仓库；
- Phase 1 起将返回 400，避免明确的 Host 前缀被静默降级；
- 这是有意的安全修正，测试需要同步更新，并在回归记录中标注行为变化。

Gateway 只调用一次 `ParsePath`：

1. `KindPing` 直接回 ping；
2. 用 `ParsedPath.Host` 做访问准入；
3. `KindReferrers` 回空索引；
4. `KindWrite` 回 405；
5. `KindManifest` / `KindBlob` 把同一个 `ParsedPath` 传给 `serveManifest` / `serveBlob`；
6. `serveManifest` / `serveBlob` 调 `PlanParsed`，不再自行解析路径。

这样 Host、Repo、referrers 和 Plan 的 `Upstream.Host`、`Name`、`Ref` 都来自同一份解析结果，不会出现“准入判成 Artifact Registry、Plan 判成 Docker Hub”的分裂。

### D6：Host 准入必须在 referrers 和缓存之前

`ServeRegistry` 的新顺序：

1. `ParsePath`；
2. `/v2/` ping：不受 Host 开关影响；
3. Host 准入：`disabled_hosts` 或 `docker_enabled` / `ghcr_enabled` 关闭 → 404；
4. referrers：只有通过 Host 准入才回空索引；
5. `KindWrite`：只有通过 Host 准入才回 405；
6. Manifest / Blob：进入 `PlanParsed`、缓存和调度。

Host 准入覆盖：

- Manifest GET / HEAD；
- Blob GET / HEAD；
- referrers；
- 已缓存内容；
- 跨 Host 共享的 `docker:blob:<digest>`；
- 不覆盖 `/v2/` ping。

禁用 Host 不查缓存、不查 Source、不回官方；共享 Blob 缓存不能成为旁路。

### D7：Blob 共享缓存沿用现有完整性机制，但必须验证

保留：

```text
docker:blob:<digest>
```

这是内容寻址缓存，允许 Host A 和 Host B 复用同一个 Blob。Phase 1 不重写下载引擎，但必须确认并测试现有路径：

- `internal/gateway/stream.go:851-891`：完整下载后计算 SHA-256，`plan.ExpectSHA` 不匹配时丢弃 partial，不提交缓存；
- `internal/gateway/gateway.go:1151-1175`：非流式路径同样在提交前比对客户端 digest 和上游声明 digest；
- `internal/gateway/stream.go` 的 `checkDigest`：上游声明摘要与内容不符时拒绝落盘；
- 已有测试 `TestRegistryBlobDigestMismatchNotCached`、`TestDigestMismatchOnMirrorNeverCached`、`TestDigestMismatchEverywhereNotCached` 必须继续通过。

Phase 1 新增的验收不是“看到 Blob 缓存命中”，而是：

1. Host A 拉取 Blob，填充共享缓存；
2. Host B 请求相同 digest，命中共享缓存，内容哈希与 digest 一致；
3. 关闭 Host B，Host B 再次请求相同 digest → 404；
4. Host A 仍然可用；
5. 重新启用 Host B，Host B 再次命中缓存；
6. 候选源返回错误摘要或半截响应时，共享缓存中没有坏内容。

如果现有代码在第 5 或第 6 项失败，Phase 1 停下来修 Blob 完整性，不得用“现有下载引擎不改”作为跳过理由。

### D8：Source 和数据库不改

Phase 1 复用：

- `sources.repo_host`：每个 Source 精确归属一个 Host；
- `sources.registry_cap` + `registry_path_mode`：由 Host Probe 写入；
- `registry_host_recovery` / `registry_host_gen`：继续按 `(source, host, gen)` 隔离健康、冷却和凭据代次；
- `RegistryCandidatesRaw(host)`：继续只查精确 Host。

因此 Phase 1 **不新增表、不改 Schema、不改 db-migrate baseline**。`<location>-docker.pkg.dev` 只需让 `registryhost.Check()` 接受该 Host，Source 写入和候选查询即可复用现有路径。

### D9：匿名 Realm 覆盖第一批

- `gcr.io`：现有 `DefaultRealms` 足够。
- `registry.k8s.io`：现有 `DefaultRealms` 足够。
- `<location>-docker.pkg.dev`：新增动态 Realm 解析，允许 `https://<实际 Host>`；不接受其他域名。
- `registry.gitlab.com`：实际 Challenge 为 `https://gitlab.com/jwt/auth`，白名单按主机 `gitlab.com`；Gateway 的 Bearer 传输同样允许这一条跨 Host 官方 Realm，其他跨 Host Realm 仍拒绝。
- `public.ecr.aws`：实际 Challenge 为 `https://public.ecr.aws/token/`，白名单按主机 `public.ecr.aws`。
- `cgr.dev`：实际 Challenge 为 `https://cgr.dev/token`，白名单按主机 `cgr.dev`。
- `mcr.microsoft.com`：匿名 `/v2/` 直接 200，无 Bearer Challenge；单独测试，不构造 Token 流程。
- 不把所有 `*.pkg.dev` 一律放行；只允许与请求 Host 完全相同的 Realm 主机。
- `lscr.io` 的实际 Realm 已按真实 Challenge 修正为 `https://ghcr.io`，但本批仍不纳入 `multi_origin_hosts`；待独立验收后再启用。

本批已将 GitLab、ECR Public、Chainguard 的 Realm 纳入实际 Challenge 测试；其余未纳入第一批的 Host 仍待后续接入。

### D10：多源范围只有一个配置来源

`multi_origin_hosts` 是唯一来源，不再有配置总开关或环境变量覆盖：

- 配置非空：列表内 Host 进入 `registry:<host>`；
- 配置为空：没有 Host 使用多源；
- 应急关闭：清空 `multi_origin_hosts` 并重启；
- 旧环境变量 `ML_REGISTRY_MULTI_ORIGIN` 不再读取。

`main` 只做一次切片复制，避免运行时修改配置对象：

```go
func copyMultiOriginHosts(hosts []string) []string {
    return append([]string(nil), hosts...)
}
```

`registryadapter.New()` 不读取任何多源环境变量。

## 3. 代码变更清单

### 3.1 `internal/registryhost/registryhost.go`

新增：

- `IsArtifactRegistry(host string) bool`：严格匹配 `<location>-docker.pkg.dev`，规则见 D4。
- `Allowed(host)`：先查 11 个精确 Host，再查 `IsArtifactRegistry`。
- `Check(raw)`：沿用 `Normalize` + `Allowed`，因此 Source 写入会自动接受合法的 `us-docker.pkg.dev`。

严格校验：

- `location` 长度 1–63；
- 只允许小写字母、数字、连字符；
- 首尾不能是连字符；
- 不允许连续 `--`；
- 不允许点号；
- 必须恰好三个 Label。

不修改：

- `defaultHosts` 的 11 个精确项；
- `Hosts()` 的副本语义；
- `Normalize()` 对端口、userinfo、IP、空标签的拒绝。

测试：

- `TestCheckWhitelist` 增加合法/非法 Artifact Registry 表；
- `TestArtifactRegistryLocation` 覆盖 D4 全部行；
- `TestHostsCopy` 仍断言 11 个精确 Host。

### 3.2 `internal/adapter/registryadapter/registry.go`

新增：

```go
type ParsedPath struct {
    Kind  Kind
    Host  string
    Repo  string
    Name  string
    Ref   string
}

func (a *Adapter) ParsePath(path string) (ParsedPath, error)
func (a *Adapter) PlanParsed(r *http.Request, p ParsedPath) (*adapter.Plan, error)
```

修改：

- `Route()` 变成 `ParsePath()` 的兼容包装；
- `Plan()` 变成 `ParsePath()` + `PlanParsed()`；
- `parseRepo()` 为唯一 Host 解析函数；
- `splitHost()` 只作为兼容包装，内部调用 `parseRepo()`；
- `hostAllowed()`：

```go
func (a *Adapter) hostAllowed(host string) bool {
    if !registryhost.Allowed(host) {
        return false
    }
    if a.Hosts == nil {
        return true
    }
    if a.Hosts[host] {
        return true
    }
    // Artifact Registry 的动态模式来自全局白名单；
    // 旧 Hosts map 不能把它重新关掉。
    return registryhost.IsArtifactRegistry(host)
}
```

这里的 `Hosts` 语义固定为“额外的精确 Host 限制”，不是全局白名单的替代品。生产装配使用 nil；测试可以用非 nil map 验证动态 Host 仍然通过。

- `sched()`：

```go
if a.multiOriginHost(host) && foreign && !isGhcrHost(host) {
    return "registry", "registry:" + host, false
}
return a.kindForHost(host, foreign), "", a.officialOnly(host, foreign)
```

- `MultiOriginHosts` 字段保存范围；`multiOriginHost(host)` 支持精确 Host 和 `*.pkg.dev` 模式；空列表表示没有 Host 使用多源；
- 不在 `MultiOriginHosts` 的 Foreign Host 保持旧行为，不能因数据库已有 Source 而被激活。

`parseRepo()` 规则：

```text
首段不含 "." → 默认上游 + 原 repo
首段含 "." 且是 docker.io → registry-1.docker.io（或当前默认上游）+ 去前缀
首段含 "." 且 hostAllowed → 该 Host + 去前缀
首段含 "." 且不允许 → ErrUnknownHost
```

## 6. 发布、回滚与兼容性

### 6.1 发布

- 只改配置和运行时逻辑，不改 Schema，不需要 `db-migrate`。应用版本 3.5.8；`schema.Version` 仍为 3.5.7。
- 配置项标 `Restart: true`，保存后重启网关生效。
- 默认 `multi_origin_hosts` 含第一批 8 个匹配项、`disabled_hosts=[]`；没有单独总开关。
- 先做只读冒烟，再接入 Source。

### 6.2 回滚

- `multi_origin_hosts: []`：所有 Host 恢复 3.5.7 的旧策略；这是唯一的多源应急关闭方式。
- 单个 Host 出问题：加入 `disabled_hosts`，只阻断访问。
- 单个 Host 不使用 Source：从 `multi_origin_hosts` 移除，官方直连仍可用。
- 不需要回滚数据库；Source / recovery 数据保留。

### 6.3 兼容性

- 老配置文件没有新字段：`multi_origin_hosts` 默认含第一批 8 个匹配项，`disabled_hosts` 空；不再有 `multi_origin` 字段。旧配置若仍保留 `multi_origin`，会被当作未知字段忽略并提示，不再产生行为。
- `ML_REGISTRY_MULTI_ORIGIN` 不再读取；旧环境变量会被忽略。
- 现有 `docker_enabled` / `ghcr_enabled` 语义不变。
- `multi_origin_hosts` 空表示“没有 Host 使用多源”，不是“全部”。

## 7. 不在本批范围

- `lscr.io` 的完整接入与多源调度（Realm 已修正，仍待独立验收）；
- 未纳入第一批的 Foreign Registry；
- 为未纳入 Host 激活 Source 或多源候选；
- Gateway-CredStore 私有凭据闭环；
- 同 Host 多 Source 的正式验收（数据模型已支持，后续验收）；
- Manifest 星标竞速、Blob 竞速；
- 站点映射表、一源多 Host；
- Host 级 UI 管理页（本批只提供配置列表字段）。

## 8. 已知问题（需在后续验收前处理）

1. **`lscr.io` Realm 已修正**：实际 Challenge 是 `https://ghcr.io/token`，`DefaultRealms` 已改为 `https://ghcr.io`；但本批仍不启用该 Host 的多源调度，待独立验收。
2. **MCR 无 Bearer Challenge**：`mcr.microsoft.com/v2/` 直接 200；不要为了统一而强行构造 Token 流程。
3. **`pkg.dev` 只支持精确模式**：`*.pkg.dev` 只是 Artifact Registry 模式的配置简写，运行时仍必须是 `<location>-docker.pkg.dev`，不能放行所有 `*.pkg.dev`。
4. **真实 Host 可用性受网络影响**：本地 fixture 通过不等于公网可用；验收记录必须区分“fixture 通过”和“真实拉取通过”。
5. **未知 Host 前缀行为变化**：首段带点且不在白名单的路径将从“按 Hub 仓库处理”改为 400；这是有意的安全修正，回归记录必须标注。

## 9. 实施顺序

| 顺序 | 工作 | 交付要求 |
|---|---|---|
| 1 | `registryhost` | 严格 Artifact Registry 模式、DNS 校验、单元测试 |
| 2 | Config | `multi_origin_hosts`、`disabled_hosts`、校验、文档、面板字段；不设总开关 |
| 3 | Adapter | `ParsePath`/`PlanParsed`、严格 Host 解析、`hostAllowed`、范围调度、单元测试 |
| 4 | Gateway | Host 准入前置、referrers/缓存/Blob 阻断、所有方法测试 |
| 5 | `v2auth` | Artifact Registry 动态 Realm、测试 |
| 6 | 装配 | 范围只来自配置、`main` 装配、日志 |
| 7 | 集成测试 | Source 命中、官方兜底、范围不扩大、共享 Blob |
| 8 | 真实测试 | 第一批 8 个匹配项（不含 lscr）的匿名公开仓库拉取和固定 Digest 记录 |
| 9 | 全量回归 | `go test ./...`、`go vet ./...` |
| 10 | 评审复核 | 已完成：第 10 节逐项签字；真实公开 Host 与真实进程 Source 证据见 5.4、5.5 |

每个阶段独立提交，避免一次大改难以定位回归。
