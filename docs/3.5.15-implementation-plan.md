# 3.5.15 实施计划

日期：2026-11-17
基线：`6e07752`（3.5.14c / v3.5.14）
唯一设计权威：`docs/registry-roadmap-v1.6.md` 3.5.15 章节（1441-1913 行）

## 0. 与 1.6 的边界确认（先读后写）

| 1.6 要求 | 现状（基线 6e07752） | 本版动作 |
|---|---|---|
| 不重建 CredStore | `internal/secret/creds.go` 已有 `registry_creds.enc` + AEAD + `Reconcile` | 只扩展接口与状态机，不新增文件/表/generation |
| 不新增平行凭据存储 | 唯一权威 `registry_host_gen` + `cred_digest` | 复用；只在 `meta` 增加 `registry_cache_epoch` |
| 不改 Schema 迁移基线 | Schema 3.5.14 / `7e5d71a7…` | 不动 `canonical.sql`、不动 `schema.Version` |
| `PutCredential` 统一写入口 | 只有 `Put(rawHost, user, pass)` | 新增 `PutCredential`，`Put` 降级为包装 |
| 认证模式枚举 | `Credential.TokenMethod/TokenAuth` 自由字符串 | 新增 `AuthMode` 枚举 + 严格校验 |
| Ready/Pending/Quarantined/Error | 只有 `reconciled` 全局布尔 + 三种错误 | 新增按 Host 状态机与 `ReconcileHost` |
| 管理 API/UI | 无 | 新增 `/api/credentials*` + 设置页面板 |
| 审计可靠 | `Audit()` 异步队列，满即丢 | 新增 `ApplyCredWrite` 同步审计（同事务） |
| 私有认证 | 完全没有 | 新增 transport 层匿名优先 + 401 后认证 |
| 缓存绕过 / epoch | 无 | 私有 Host 直通不落缓存；键加 epoch |
| 身份门禁 | 只有 `PolicySnapshot` + SourceID | 新增 `IdentityKind` + 受控构造 + `AuthorizeCredential` |
| Official `CredGen` | `OfficialPolicy.Resolve` 恒 0 | 由 `StorePolicy` 读 `registry_host_gen` 填充 |

## 1. 改动清单（按可提交单元）

### C1 — 15-A 存储层：同步审计 + 乐观并发

文件：
- `internal/store/credwrite.go`（新）
- `internal/store/host.go`（复用 `ApplyCredChanges` 内部逻辑）

接口：
```go
type CredWrite struct {
    Host        string
    Digest      string
    ExpectedGen *int64      // nil = 不校验
    Audit       *AuditEvent // 同事务同步写
}
type CredWriteResult struct { Gen int64; Changed bool }
var ErrCredGenConflict = errors.New(...)
func (s *Store) ApplyCredWrite(CredWrite) (CredWriteResult, error)
```
- 单 `BEGIN IMMEDIATE` 事务：CAS 校验 → gen+1/digest → 清 `effective_status`/recovery（复用现有语义）→ 审计 INSERT。
- digest 与现值相同 ⇒ `Changed=false`，不 bump、不写审计（幂等）。
- 测试：`internal/store/credwrite_test.go`（CAS 冲突、幂等、审计同事务、两连接并发）。

### C2 — 15-A 凭据接口与状态机

文件：
- `internal/secret/creds.go`（改造）
- `internal/secret/credstate.go`（新）

接口：
```go
type AuthMode string // basic | bearer_token_basic | bearer_token_none
func (m AuthMode) Validate(Credential) error
type State string    // Absent|Ready|Pending|Quarantined|Error
type HostStatus struct { Host, State, Reason string; Gen int64; Username, Mode string; UpdatedAt int64 }
func (s *Store) PutCredential(rawHost string, c Credential, expectedGen *int64) (PutResult, error)
func (s *Store) DeleteCredential(rawHost string, expectedGen *int64) (PutResult, error)
func (s *Store) Status(rawHost string) (HostStatus, error)
func (s *Store) ListStatus() ([]HostStatus, error)
func (s *Store) ReconcileHost(rawHost string) (HostStatus, error)
```
- 严格校验：`TokenMethod ∈ {"", GET}`（POST 拒绝）、`TokenAuth ∈ {"", none, basic}`、`basic` 必须有用户名密码、`bearer_token_none` 必须显式标记。
- 幂等：解密现有记录逐字段比较；完全相同 ⇒ 不写文件、不 bump、不失效 Token。
- 记录级损坏（AEAD/JSON）只隔离该 Host（`Quarantined`）；文件级损坏（顶层 JSON/版本）全局 fail closed。
- 写入顺序：校验 → `mu`+`flock` → 临时文件/fsync/rename/父目录 fsync → DB 事务 → Ready；DB 失败 ⇒ `Pending`（文件保留）。
- `Put` 保留为包装，内部同一路径。
- 测试：`internal/secret/credstate_test.go`（模式校验、幂等、Pending、Quarantined、单 Host 隔离、Delete 幂等、409 语义）。

### C3 — 15-C 身份与门禁

文件：
- `internal/v2auth/identity.go`（新）
- `internal/v2auth/policy.go`（`CredGenKnown`）
- `internal/store/policy.go`（官方 resolver 填 `CredGen`）
- `internal/v2auth/redirect.go`（新）

接口：
```go
type IdentityKind uint8 // Unknown=0, Official, Candidate
type Identity struct{ kind IdentityKind; host string; sourceID int64 } // 私有字段
func NewOfficialIdentity(host string) (Identity, error)
func NewCandidateIdentity(sourceID int64, host string) (Identity, error)
func WithIdentity(ctx, Identity) context.Context
func AuthorizeCredential(ctx context.Context, snap CredentialSnapshot) error
func CheckRedirect(kind RedirectKind, from, to *url.URL, hop int) error
```
- `AuthorizeCredential`：Official、SourceID=0、`PolicySnapshot.Official`、Host 规范化相等、`HasCredential`、`Generation==CredGen && CredGenKnown`、模式与字段一致。
- `StorePolicy.Resolve(sourceID=0)` 读 `registry_host_gen`，缺行 `CredGenKnown=false`；DB 错误 fail closed。
- 重定向：Registry 5 跳 / Token 3 跳同源 / CDN 5 跳 GET·HEAD，HTTPS 降级拒绝，跨 Host 清 Authorization。
- 测试：`internal/v2auth/identity_test.go`、`redirect_test.go`、`internal/store/policy_official_test.go`。

### C4 — 15-B transport：匿名优先 + 401 后认证

文件：
- `internal/gateway/registryauth.go`（改造 `bearerTransport`）
- `internal/gateway/privneg.go`（新，负缓存）
- `internal/gateway/registryauth_private_test.go`（新）

行为：
1. 无凭据/无身份 ⇒ 现有匿名 Bearer 行为不变。
2. 有身份 + 凭据 ⇒ 先匿名发一次；401 + 合法 Challenge ⇒ `AuthorizeCredential` ⇒ Basic 直连或 Bearer Token（Basic 仅 Token 端点）。
3. Token 请求带 `account=<user>`（basic 模式）。
4. 带 Token 仍 401 ⇒ 删除该 key、重取一次、重试一次；二次 401 直接返回。
5. Token 端点 401/403 ⇒ `token_auth_failed`；5xx ⇒ `token_upstream_error`。
6. 错误密码负缓存：Host+模式 30s→5m 指数退避；凭据变更清除。
7. 401/403 不计 Source 健康、不触发候选回退。

### C5 — 15-B 缓存隔离与 epoch

文件：
- `internal/gateway/registry.go`（私有 Host 直通）
- `internal/adapter/registryadapter/registry.go`（epoch 键）
- `internal/gateway/cdn.go`、`internal/store/coldlayers.go`（键前缀兼容）
- `internal/store/epoch.go`（新）

行为：
- `registry.private_auth_hosts` 命中的 Host：`CacheGet` 之前直接走 `passThrough`，读/写都不进共享缓存；`plan.OfficialOnly=true`；HEAD/Range/resume 同一路径。
- 键格式 `docker:m:<epoch>:…` / `docker:b:<epoch>:…`；epoch=0 保持旧格式（未启用私有认证的部署零变化），启用私有认证时强制 epoch≥1。
- 启动：读 `meta.registry_cache_epoch`；启用私有认证且为 0 ⇒ 递增并持久化；读失败拒绝启动私有认证。
- 新增私有 Host 时递增 epoch（全局失效）。
- 旧 epoch 物理清理：`CacheEpochSweep`（限速、进度、重试、审计）由 janitor 调用。

### C6 — 15-B 配置与准入

文件：`internal/config/config.go`、`internal/gateway/gateway.go`
- `registry.private_auth_enabled`（默认 false）、`registry.private_auth_hosts`。
- 校验：enabled ⇒ `auth.require_token=true` 且存在 Access Token；hosts ⊆ `v2auth.PrivateAuthAllowlist()`；否则拒绝启动。
- 运行时：请求路径检查 `requireToken && tokenConfigured`，失效即 fail closed。

### C7 — 15-A 管理 API

文件：`internal/api/credentials.go`（新）、`internal/api/api.go`（路由）
- `GET /api/credentials`、`GET|PUT|DELETE /api/credentials/{host}`、`POST …/verify`、`POST …/reconcile`。
- `guard(csrf(...))`、HTTPS/`X-Forwarded-Proto` 检查、`no-store`、64 KiB 上限、`expected_gen` 409。
- 审计 `credential_put/delete/verify/reconcile`；不写密码/Token/Authorization。
- 测试：`internal/api/credentials_test.go`。

### C8 — 15-A UI

文件：`internal/api/web/settings.html`
- 凭据卡片：Host 列表（`credentialCapableHosts()`）、状态、用户名、模式、gen；新增/更新/删除；无查看密码入口。

### C9 — 15-C Probe 分离

文件：`internal/runner/hostprobe.go`、`internal/runner/hostprobe_test.go`
- 候选 Source 探测：不读、不传官方凭据；401/403 ⇒ `auth_error`/Inconclusive，不标 Unsupported。
- 官方私有验证：独立入口（`VerifyOfficialCredential`），`IdentityKind=Official`、`SourceID=0`、不走缓存、不写 caps/recovery。

### C10 — 15-D 冻结与门禁

文件：`internal/v2auth/allowlist.go`、`docs/3.5.15-*.md`
- 代码 allowlist：`quay.io`、`gcr.io` 可配凭据；`registry.k8s.io`/`mcr.microsoft.com`/`lscr.io`/`public.ecr.aws`/`cgr.dev` 仅匿名；`*.pkg.dev`、`docker.io`、`ghcr.io`、`registry.gitlab.com` 不出现在凭据入口。
- `credentialHost` 继续拒绝端口/IP/localhost/私网。
