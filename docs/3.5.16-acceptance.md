## 2. 代码复核结论（对照 1.6 语义）

| 复核点 | 结论 | 证据 |
| --- | --- | --- |
| 资格判定唯一入口 | 通过：只有 `serveManifest` 调 `evaluateRegistryRace`，执行层只读 `plan.RaceReady` | `internal/gateway/registry.go:415` 附近；`registryrace.go` 头注释 |
| 关闭态字节级不变 | 通过：无 settings 键 → `RaceReady=false`、`FlightPolicy` 留空 → `flightKeyFor` 返回 `plan.CacheKey`，GET/HEAD 共享同一 Flight | `TestRaceDefaultsOff`、`TestRaceHeadNotJoinRaceFlight` 的反向断言（关闭态 `hits==1`） |
| HEAD 不竞速且顺序回源 | 通过：`evaluateRegistryRace` 对 `HEAD` 置 `Sequential` 并返回；真实进程 `ineligible{reason="head"}` 计数增长、`race_started` 不变 | `TestRaceHeadSequential`、`TestRaceGetNotJoinHeadFlight`、`TestRaceHeadCoalesce`；进程 A/B 实测 |
| 可变 Tag 不进竞速 | 通过：仅 `ExpectSHA != ""` 条目可竞速 | `TestRaceTagNotRaced`；真实进程 D1（tag 请求 → `hedge_triggered` 增长、`race_started` 不变） |
| 竞速与 hedge 不同层 | 通过：竞速时 `hedge` 关闭（同层互斥），回退链不加 hedge | `TestRaceChainSemantics`；真实进程 A：race 期间 `hedge_triggered_total` 不变 |
| 第二路预算是非阻塞 | 通过：`TryAcquireLease` 拿不到名额 → `budget_skipped++`、整场退回顺序，第一路不受影响 | `TestRaceSecondCandidateBudget`（预占名额，断言第二路 0 请求） |
| 至多两路 | 通过：`raceEligibleTargets` 截断 2 | `TestRaceAtMostTwoCandidates` |
| 胜者正文失败必须回退 | 通过：`raceManifest` 校验 Digest/长度/读取错误 → `body_failures++`/`fallback++`，回到顺序路径且**不写缓存** | `TestRaceWinnerBodyFailureFallsBack`（3 子用例）；真实进程 B：截断边 → 200/正确 Digest/唯一缓存条目来自官方 |
| 认证/身份不被穿透 | 通过：`OfficialOnly`、私有 host 白名单、`Rewrite` 失败即不入候选 | `TestRaceOfficialOnlyNoRace`、`TestRaceNoOfficialBackfill` |
| Claim 请求级令牌 | 通过：竞速不引入进程级共享状态，`taken[]` 只在单次请求内传递 attempt 归属 | `registryrace.go` `launch()`/`raceManifest` |
| 星标变更必须审计 | 通过：仅变化时写一条 `source_star`，探测不写 | `TestStarRaceAuditOnStarChange` |

**Frozen 不变量核对**：FlightKey 隔离的是执行态（`CacheKey` + policy 命名空间），不是 HTTP 方法；关闭态/合格源 <2 时 GET 与 HEAD 共享 `plan.CacheKey` 顺序 Flight；≥2 合格源时 GET 走 `registry-race` Flight，HEAD 永不进入。AB-5：A 的资格判定完全独立，B 将来只复用 `fetchRace` 执行机制。

### 7.1 A07 fallback 联动（必过门禁）

六条证明点核对：

| 证明点 | 证据层 | 证据 |
|---|---|---|
| main 存在 fallback 时仍能执行 A 竞速 | 代码测试 | `TestRaceChainSemantics`：主链 A=2 命中，断言“主链应形成双路竞速” |
| fb 链不叠加同层 Hedge | 代码测试 + 真实进程指标 | `TestRaceChainSemantics` 断言 `fbHits==0`；真实进程 `race_fallback_total=0`、竞速期间 `hedge_*` 不变 |
| 不形成 2×2 四路并发 | 代码测试 | `TestRaceChainSemantics` + 至多两路截断 `TestRaceAtMostTwoCandidates` |
| main 失败后 fb 接管 | 代码测试 + **真实进程 REAL_PASS** | `TestRaceChainSemantics` fb 链执行；补充轮真实进程用 ghcr-only 镜像 `zero-desktop/zero-desktop@sha256:ff12a8f8…` 验证：no-seed + discover 未启动的干净窗口内，debug 日志铁证 main 链 `registry-1.docker.io` 返回 401（`源要求鉴权，换下一个 … status=401`），最终请求返回 200 且正文 SHA-256 == 请求 Digest `ff12a8f8…`；带前缀 `ghcr.io/...` 同镜像 200 证明 ghcr 通道可服务该镜像。main 唯一 target 失败、无加速源候选，200 唯一来源是 fb 链 ghcr.io 备用站点 |
| main 胜出不泄漏 fb 资源 | 代码测试 + 真实进程 | `TestRaceMainWinDoesNotRememberFallback`（主链成功不记 fallback）；`TestTrustedRacesDoNotLeakGoroutines`（1000 次后 goroutine 回落） |
| 取消单一 attempt 不误取消其他 | 代码测试 | `TestRaceHeadNotJoinRaceFlight` / `raceManifest` 每 attempt 独立 Context + `taken[]` 请求级令牌 |

真实进程资源观测（连续 50 次竞速压测后）：进程线程数 **13**、FD **16**，无增长趋势；累计 `race_started=57`、`wins{rank=1}=35 / rank=2=22`（两路均胜出过，证明为真竞速）、`cancelled=27`（输家被取消）、`body_failures=0`、`fallback=0`、`budget_skipped=0`。

A07 结论：**六条证明点全部通过**。其中「main 失败→fb 接管」已用 ghcr-only 镜像在真实进程上端到端验证，达到 **REAL_PASS**（真实二进制 + 真实公共 ghcr 源 + main 真实 401 失败 + 正文 Digest 一致）；其余五条为代码测试 + 真实进程指标佐证。六条无 `NOT_EXECUTED`。
