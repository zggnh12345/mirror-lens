# 3.5.17 统一执行框架设计（冻结输入）

> 本文件是 17b 唯一执行框架权威设计。符号当前不存在于 d1ea272，全部为 17b 新建。
> 基线：d1ea272；1.6 SHA 76b81e99。配套：pre-freeze-audit.md、schema-design.md、test-matrix.md、implementation-plan.md。

## 1. 统一术语表（唯一含义 / 所属账本 / 禁止混用）

| 术语 | 唯一含义 | 记账对象 | 禁止混用 |
| --- | --- | --- | --- |
| RequestScope | 一个客户端请求的全生命周期容器 | 统一拥有 R/P/结果账本 | ≠单次 Do、≠Attempt、≠Chain |
| Registry | 规范化逻辑 Registry 身份（logical host） | 身份域 | ≠Source、≠物理 URL host |
| Source | 候选镜像源实体（sources.id） | 配置域 | ≠Registry（一源可多 Host） |
| Identity | (规范化 Registry, Repository, ManifestIdentity) | Claim 域 | ≠认证上下文（凭据不参与身份） |
| Chain | Main/A/B/fb 等独立执行链，含多 Attempt | Chain 生命周期 | ≠RequestScope、≠Attempt |
| Attempt | 一个逻辑候选执行单元 | 符合 R 规则时消耗 R | ≠RoundTrip、≠RangeWork |
| RoundTrip | 底层 Transport 的一次实际应用层派发 | 每次消耗 P | ≠逻辑 Attempt |
| RangeWork | Midfill/tryParallel 的 Range 工作单元 | 消耗 RangeWorkCap 与 P | 不自动占 R |
| Claim | Scope+Identity 的跨 Chain 独占权 | Claim 域（三态） | ≠预算、≠Lease |
| ClaimState | Reserved/Dispatched/Released | Claim 三态 | ≠AttemptState |
| AttemptState | Prepared/Dispatched/Aborted/Completed | Attempt 四态 | ≠ClaimState |
| Reserved/Dispatched/Released | Claim 三态的具体取值 | Claim 域 | Dispatched 不可被别链接管 |
| Prepared/Dispatched/Aborted/Completed | Attempt 四态的具体取值 | Chain 内 | ≠Claim 三态 |
| R | 逻辑 Attempt 累计硬上限 = 16 | 预算域 | ≠P、≠物理请求 |
| P | 应用层受控 RoundTrip 派发硬上限 = 8192 | 预算域 | ≠物理网络发送、≠R |
| G | 全服务 RequestScope 并发容量 | 全局 | ≠P（累计） |
| M/C/A | M=4、C=2、A≤2 | 预算推导 | 不重开 |
| Authority | 单候选软比对 + 最终兜底，一次 Attempt | RequestScope | ≠独立 Scope |
| fb | 备用链，受静态抑制 | Chain | ≠A 站内竞速 |
| Hedge | 响应头阶段额外分支 | RequestScope | ≠B Digest 投票 |
| Midfill | 慢速中途分片接管 | RequestScope | 256 是单计划分段非累计 |
| Preflight | 1 字节探活，一轮共享快照 | RequestScope | ≠累计预算 |
| RegistryRetryToken | per-Registry 重试令牌（B16） | Chain | ≠通用 RetryToken |
| Outcome | 单 Attempt 结果分类 OK/Miss/Auth/Fail | 结果账本 | ≠最终仲裁结论 |
| Manifest 投票窗口 | 200ms Digest 投票，独立于响应头竞速 | RequestScope | ≠Hedge 响应头竞速 |
| 动态排序样本 | 现有排序按 Rev 稳定排序；AIMD 3.0 起下线 | 调度域 | 不改 M 成员集合 |

关键区别（冻结）：
- 一个逻辑 Attempt 可触发多个 RoundTrip。
- 一次 Token 获取是 P 派发，不是新建一个 R Attempt。
- 一个 RangeWork 消耗 P 与 RangeWorkCap，但不自动占用 R=16。
- Claim Dispatched 不代表下载成功，只代表至少一个 Attempt 越过发送提交边界。

## 2. 组件与生命周期

### 2.1 RequestScope
- 创建：客户端请求进入 registry/manifest/blob 执行链时。
- 关闭：响应写完/取消/错误仲裁完成，所有 Body 关闭、Lease 释放后。
- 持有：R 账本、P 账本、结果账本（AttemptResult[]）、Generation 快照 + 候选快照、所有 Chain 注册、所有 Attempt 登记、父 Context 取消传播。
- B/fb/Authority/Hedge/Midfill 不得各自创建独立 RequestScope。

### 2.2 Identity Claim
- ClaimKey = (RequestScope, Identity)，Identity = (规范化 Registry, Repository, ManifestIdentity)。
- 跨 Chain 竞争同一 Claim：同 Identity 只允许一条 Chain 获得 Reserved→Dispatched。
- 同 Chain 多个 Attempt 可共享同一 Claim（如 A 站内多 Source）。
- 认证上下文不参与身份等价，但继续影响凭据与授权策略。
- 三态：Reserved（预占）→ Dispatched（已越过发送提交边界）→ Released（完成/失败/取消释放）。
- Dispatched 后 Chain 关闭不得被另一 Chain 接管；Claim 已 Dispatched 的取消走 Aborted，不回退为 Reserved。

### 2.3 Chain
- 类型：Main / A / B / fb。
- 生命周期：Created → Active → Closing → Closed。
- Closing 后不得 RegisterAttempt（T53）。
- 每 Chain 有自己的 Lease 归属与 Attempt 列表。

### 2.4 Attempt
- 四态：Prepared → Dispatched → Aborted / Completed（T53/T54/T55）。
- Prepared 阶段取消：不形成结果记录、不消耗 R。
- Dispatched：越过发送提交边界，消耗 R（符合 R 规则时）并计 P。
- Aborted：取消/失败退出；Completed：成功提交。
- Body 关闭、Attempt 退出、Lease 释放必须幂等且有明确所有权。

### 2.5 RegistryRetryToken
- per-Registry、per-RequestScope 的重试令牌（B16）。
- 顺序路径的每次 Registry 重试须持有令牌；令牌耗尽不再重试该 Registry。

### 2.6 GlobalLeasePool / 配额
- 复用现有 scheduler.Lease/Token（lease.go:24-81,208）与 AcquireLease/TryAcquireLease（scheduler.go:838/853）。
- Preflight 独立配额 preSem（source_quota.go:initSems），容量 preflight_concurrency=4，不进 max_per_source 账本。
- Relay/Git 独立配额保持现状。

## 3. R/P/G 预算规则

### 3.1 R（逻辑 Attempt）
- R=16，逻辑 Attempt 累计硬上限，保留原推导语义，不因 Hedge/Midfill/Range 重解释 M/A/C/fb/Authority。
- 仅 Attempt 越过 Dispatched 且符合 R 规则时消耗。

### 3.2 P（应用层受控派发）
- P=8192，RequestScope 级应用层受控 RoundTrip 派发硬上限。
- 计量点：包裹 registryAuthTransport.base（底层 http.Transport 之上），Token 请求统一走此包装，解决 t.base 绕行。
- 必须计入：Main/A/B/fb/Authority、Hedge 额外分支、Preflight probeTarget、每个 Range 请求、trySwitch、Bearer 匿名挑战与认证重发、Token 获取/刷新、Registry 重定向、Token 端点重定向。
- Transport 内部自动重试不计入 P；不宣称 P 是 TCP/物理网络发送总次数。
- 两阶段门控：ReserveP（原子预留，检查 Scope 与父 Context）→ CommitP（调用底层 RoundTrip 前正式消耗）；未提交即取消释放预留；已提交无论结果不返还；绝不超过 8192。
- 耗尽处理（冻结）：
  - 未发响应头：HTTP 503 + `Cache-Control: no-store` + 内部错误码 `REQUEST_BUDGET_EXHAUSTED`；不冷却 Source；不再回退请求。
  - 已发正文：取消剩余 Attempt、关闭所有未完成 Body、不提交完整缓存、清理未验证/不完整部分文件、中断传输、记录指标与结构化日志。
  - 预算耗尽不是上游故障，不污染 Source 成功率/失败率/动态排序样本。
  - P 耗尽作为独立最高优先级通道，不归入 policyErr/Auth/Miss/Fail 任一档（AUD-04-6 错误优先级表须单列）。

### 3.3 RangeWork 与 Midfill 约束
- RangeWorkCap=1024；分段计划上限 256；每 Range 分段最多 4 个目标（含官方源）；Preflight 上限 min(实际目标数, 2×Workers)。
- 256×4=1024，与 RangeWorkCap 精确一致。
- 每 RequestScope 只执行一轮 Preflight；tryParallel 与 midFill 共享 Preflight 结果和 Range 工作量账本。
- 每 Range 第 5 个及以后目标不再请求，防止对全部候选逐一反复循环。
- RangeWork 消耗 P 与 RangeWorkCap，不自动占 R。

### 3.4 认证 Scope 级上限
- 每 RequestScope、每 (Registry, Source, Realm) 最多一次强制 Token 刷新周期。
- Token 缓存（1024）与 singleflight 继续复用。
- 刷新后再次 401 → 结束该认证路径，不允许同一 Scope 对同一 Realm 无限刷新。
- Registry 重定向上限 5 跳、Token 重定向上限 3 跳（沿用 v2auth.RedirectPolicy）。
- 66 仅作单次请求链路极端诊断上界，不作每 Range 固定倍数。

### 3.5 G（全服务并发）
- G = N × max(W+1, C×A, 2) + 4；N=200、W=4（默认 2~16）、C=2、A≤2、Preflight 池 4。
- 默认 G=1004；W=16 时 G=3404。
- limits.enabled=false 时外部 HTTP 入口限流可关，但内部 Registry RequestScope 仍用 cfg.Limits.GlobalConcurrency 作为 N 硬上限，不得无限大。

## 4. 状态机

### 4.1 Claim（三态）
Reserved ──发送提交──> Dispatched ──完成/失败/取消──> Released
- Dispatched 不可回退为 Reserved；取消走 Aborted（Attempt 侧），Claim 释放。
- 同 Identity 跨 Chain 只允许一条获 Reserved。

### 4.2 Attempt（四态）
Prepared ──发送提交──> Dispatched ──成功──> Completed
                              └──失败/取消──> Aborted
- Prepared 取消不形成结果记录、不消耗 R/P。
- Dispatched 取消记录 Cancelled（Attempt 终止态），阻止全 Miss。

### 4.3 Manifest 投票（独立于 Claim 与响应头竞速）
COLLECTING ──首个正文 Digest 已验证候选──启动 200ms
COLLECTING ──≥2 不同逻辑 Registry 且不同 source_id 且 Digest 一致──> CONFIRMED
COLLECTING ──只有一个有效候选，等待窗口关闭──> AUTHORITY_COMPARE
COLLECTING ──两候选 Digest 不一致 / 零有效候选──继续顺序补位（不确认）
任意 ──窗口关闭──> WINDOW_CLOSED（锁定结论）
- 投票对象必须是正文已完整读取且 Digest 已校验的结果；仅响应头 Docker-Content-Digest 不构成有效票。
- "不同 Registry"按规范化逻辑 Registry host 判定，且要求不同 source_id；同一 Source 不通过别名贡献两票。
- 窗口外到达的响应只关闭 Body/清理资源，不改已锁定结论，不重开窗口。
- 投票只决定 Manifest 身份可信度，不决定 Claim 提交资格；Claim Dispatched 不等投票。

### 4.4 Authority 唯一执行
- 单候选有效时 Authority 只请求一次；软比对与最终兜底复用同一份结果。
- Digest 一致 → 候选身份确认；不一致 → 丢弃未确认镜像正文，Authority 正文可作权威结果交付；Authority 失败/校验失败 → 不确认候选。
- 不再发起第二次 Authority 请求。
- 两候选不一致时先走剩余可信副本顺序补位，仅既定路径需要时才用那一次 Authority 预算。

## 5. 与已冻结语义的关系

- A 站内竞速：同 Identity 多 Source 共享 Claim（T51），能力复用现有 registryrace.go 的响应头竞速与 star 资格判定，需适配统一框架。
- B 跨站：M/C/A 与 Digest 投票组合，投票独立于响应头竞速与 Claim。
- fb：静态抑制快照先于 Claim 竞争（F19/T61）；fb 进统一结果账本但保留 Chain 身份。
- Hedge：响应头阶段，独立 ictx/cancel，三指标分离，接 P 门控。
- Midfill：一轮 Preflight 共享、RangeWork 限额、Range 消耗 P 不进 R。
- A 回退：部署期全局回退；单请求混合新旧框架禁止（T62）。
