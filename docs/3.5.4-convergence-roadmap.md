## 二、阻断问题（后续版本必须先解决）

### P0-1 认证模型未覆盖业务回源

- `main.go:334-346` 创建 `CredStore` 并 `Reconcile()`，但只传给 Host Probe；
  Gateway 未接收该 `CredStore`，实际回源走 `bearerTransport` 与独立 `tokenCache`。
- 因此：**探测能认证 ≠ 实际拉取能认证**，不能据此宣称支持私有 GitLab / NVCR。
- `internal/v2auth/auth.go:142-151` `DefaultRealms()` 缺 `registry.gitlab.com`、`nvcr.io`。
- `internal/registryhost/registryhost.go:16-20` `defaultHosts` 缺 `nvcr.io`，
  且 `registryhost_test.go` 当前明确断言 `nvcr.io` 应被拒绝。
- `Credentials.tokenAuthMode()` 仅实现 GET，POST 返回 `ErrTokenMethodUnsupported`。
- 当前没有 Host 凭据的管理 API / 页面，`CredStore.Put/Delete` 只是内部方法。
- 要求：
  - 区分探测凭据与业务回源凭据；Gateway 按逻辑 Host 取凭据快照。
  - 每 Host 独立 Realm 白名单，拒绝白名单外 Realm。
  - Token 缓存键至少含 Host、Realm、Service、Scope、凭据代次。
  - 不支持的认证方式显式拒绝，不静默降级。
  - 提供凭据管理入口（API + UI）。

### P0-2 全局 Hedge 与 Registry 顺序查询冲突

`internal/gateway/gateway.go:780`：

```go
hedged := g.hedge.Enabled && len(targets) > 1 && !targets[0].fb && len(plan.Fallbacks) == 0
```

`ML_REGISTRY_MULTI_ORIGIN=1` 后，Registry 多候选会自动触发全局 Hedge（默认 `Enabled=true, AfterMS=1000`），
与“Registry 默认顺序”冲突；但不能直接关闭全局 Hedge，Hub/GHCR 依赖它。

要求：Hub/GHCR 保留现有 Hedge；`registry:<host>` 默认顺序；仅 `query_mode=star_race` 才允许竞速。

### P0-3 Registry 通道开关未按 Host 隔离

`internal/gateway/registry.go:31-42`：ghcr.io 用 `ghcrOff`，其余全部 Host 用 `dockerOff`。
于是 quay.io / lscr.io / registry.gitlab.com / registry.k8s.io / public.ecr.aws 都受 Docker 开关控制。
`docker_enabled=false` + `ghcr_enabled=true` 时，已有有效源的 LSCR/GitLab 也会被挡住。

要求：Docker / GHCR / foreign Registry 三套开关独立，foreign 开关默认关闭。

### P0-4 Manifest 官方摘要一致性未闭环

`probe.RegistryHostProbe` 有 `ExpectedDigest`（`internal/probe/registryhost.go:33-35`，校验在 319-320），
但 `internal/runner/hostprobe.go:401-415` 构造探测请求时未传 `ExpectedDigest`。

因此当前 Host 探测只能证明：正文可读、`Docker-Content-Digest` 与正文自洽；
**不能证明与官方 Manifest 一致**。

要求：
- digest 形式的 Manifest 与 Blob 必须做强摘要校验。
- tag 形式的 Manifest 需可信官方基准或明确的版本一致性策略，不能把“正文自洽”写成“官方一致”。
- 探测使用代表性 repo + tag，并传入 `ExpectedDigest`。

## 三、3.5.4 收敛范围（C1–C5）

| 阶段 | 工作 | 收敛标准 |
| --- | --- | --- |
| C1 | 数据模型定稿 | 每类状态有唯一权威写入路径与明确读取语义 |
| C2 | 迁移闭环 | 真实历史库升级、重复启动、失败回滚、备份恢复均验证 |
| C3 | 兼容边界冻结 | Hub / GHCR 旧路径与新 Registry 路径互不污染 |
| C4 | 凭据语义冻结（不接 Gateway） | 代次/摘要唯一权威；Gateway 接入归后续 A 阶段 |
| C5 | 回归验收 | 旧功能、新功能、故障恢复、并发与重启测试全部通过 |

已冻结的关键裁定：

- 采用方案 A：本阶段只归一**非 GHCR foreign Registry**；Hub 与 GHCR 保留旧能力字段。
- `repo_host` 保持 `NOT NULL DEFAULT ''`，新增 `registry_identity_state`（identified / unclassified / not_applicable），空串不再隐含 Hub。
- 六条双用途源标记 `identified + docker.io`（primary host），GHCR 能力继续由 `ghcr_cap/ghcr_prefix` 表达；identity_state 表示主 Host，不表示唯一能力。
- 禁止把 Hub 行写成 `docker.io` 后触达 Host Probe：`ListDueHostProbes` 与新 Registry 通道入口必须排除 `docker.io`、`ghcr.io`。
- **不改动** `SourceCandidates("docker"/"ghcr")` 的查询与过滤，保证旧池行为不变。
- `AddSource` / 导入 / 种子路径必须显式写入身份，禁止新源再落回 `repo_host=''` 的隐式语义。
- id 114 / 115 两条显式 `ghcr.io` 源仍在旧 GHCR 池中（`ghcr_cap=1`、usable），3.5.4 **不归档、不删除**。
- 分层健康表不合并：`source_health_scope` 的 (scope, gen) 复合主键有真实语义。
- Scheduler 视为冻结的稳定基础设施：仅允许针对可复现缺陷做局部修改。

## 四、收敛完成后的实施顺序（A–D）

| 阶段 | 内容 | 默认行为 |
| --- | --- | --- |
| A | Host 凭据管理、Realm 白名单、Gateway 实际使用凭据、独立通道开关 | 新 Registry 关闭 |
| B | 多 Registry 正式启用：候选、探测、Manifest/Blob、回退、缓存与摘要验收 | 顺序查询 |
| C | Manifest star_race | 独立开关，默认关闭 |
| D | Blob 竞速评估 | 不默认实现，单独立项 |

A 未完成前，B 只能宣称支持部分公开 Registry，不得宣称支持带凭据的 GitLab / NVCR。

## 五、竞速规则（Manifest 可做，Blob 暂缓）

- 默认 `sequential`：按序尝试已验证候选，全部失败回官方。
- `star_race`：只筛 `registry_race=true` 的源，最多两个；复用现有响应头竞速与 Lease 生命周期。
- 响应头先到不代表内容可信：胜者必须完成 Manifest 正文校验后才提交缓存。
- 输家取消、关闭 Body、释放 Lease；不得突破单源与全局并发限制。
- `registry_race` 不得复用 `trusted`。
- Blob 竞速暂缓：Body 所有权、取消边界、首字节后接管、Range/断点、`.part` 生命周期风险高于收益。

## 六、缓存身份（冻结，不改）

- Manifest：`逻辑 Registry Host + Repo + Ref + Accept`。换源不得改变 CacheKey。
- Blob：按内容摘要共享，可跨仓库复用。
- 缓存命中不依赖当前是否有可用镜像源。
- 竞速只允许胜者提交缓存。
- 测试必须同时覆盖首次 MISS 与第二次 HIT。

## 七、测试矩阵（按当前代码重组）

P0：Hub 回归（开关开/关）、GHCR 回归（开/关）、Host 隔离、Realm 白名单、Token 隔离、
凭据轮换、Manifest 摘要、Blob 摘要、Manifest 缓存隔离、Blob 跨 Host 复用、官方回退。

P1：429 隔离、Range/HEAD、中途换源、Registry 竞速（仅显式标记两个源）、
竞速取消（Body/Context/Lease）、竞速资源上限、数据库迁移与重复启动。

额外要求：
- Hub/GHCR 回归必须在 `multi_origin=true` 下执行。
- 认证必须走完整业务请求（Gateway 拉 Manifest/Blob），不能只测 `ProbeRegistryHost()`。

## 八、3.5.4 必须为 A–D 预留的约束

这是 3.5.4 的设计输入，违反任一条都会在 A/B/C 阶段返工。

1. **Host 身份用逻辑 Host**：Gateway 取凭据、拼 Realm、写 CacheKey 都以逻辑 Host（ghcr.io、gitlab.com）为准，
   不是加速源 Host；`registry_identity_state` 与 `repo_host` 必须能直接支撑这一点。
2. **健康/恢复主键保持 `(source, host, gen)`**：凭据轮换依赖 gen 失效闭环，收敛不得删除 gen 维度。
3. **候选查询保持多候选出口**：准入与排序分离，不要把 registry 候选写死为单条；后续要按 `query_mode` 过滤。
4. **通道开关留出 Host 维度**：收敛阶段不要新增依赖 `dockerOff` 的代码路径；foreign Registry 开关是独立维度。
5. **探测字段与摘要链路保留**：`ExpectedDigest`、digest 校验、Blob 的 ExpectSHA 都不得在收敛中删除或改名。
6. **缓存语义不动**：Manifest 按逻辑 Host 隔离、Blob 按摘要共享，收敛与迁移不得改变 CacheKey。
7. **Scheduler 与 Hedge 结构不动**：竞速在 C 阶段通过开关复用，不在 3.5.4 改结构。

## 九、门禁与非目标

- 门禁：3.5.4（过渡态收敛）完成前，不启动 A 阶段；A 完成前，不宣称支持私有 Registry。
- 非目标（3.5.4）：不重写 Host 调度、健康隔离、路径改写、流式回源；不做 Blob 竞速；
  不统一 Hub/GHCR 与 foreign Registry 能力模型；不支持一源多 Host；不接 Gateway 凭据。

## 十、完成定义（3.5.4）

3.5.4 结束的是**隐式、未定义的过渡态**：空 `repo_host` 不再隐含 Hub；身份由 `registry_identity_state` 表达；
Hub、GHCR、foreign Registry 的能力归属与调度入口边界明确；保留的旧路径均有 owner、保留理由、
退出条件和验收证据。双能力模型与一源多 Host 作为显式架构债留待后续版本。
