## 2. 代码变更

### 12c Source 级 Realm 策略管理

- 新增 API：
  - `GET /api/policies`：Host 汇总（Host、Source 数、有策略数）+ 当前 `multi_origin_hosts`（只读）。
  - `GET /api/policies?host=…`：该 Host 下 Source 与策略（策略缺失时 `policy=null`）。
  - `GET|PUT|DELETE /api/policies/{source_id}?host=…`：读取、替换、删除策略。
  - `GET /api/policy-audit?source_id=&limit=`：策略变更事件。
- 新增 Store：`ListRealmPolicies`、`ListPolicyHosts`、`DeleteRealmPolicy`、`ListPolicyEvents`。
- 删除即停用：`DeleteRealmPolicy` 删除策略行，运行时 `StorePolicy.Resolve` 返回 `ErrPolicyMissing`，fail closed。
- 设置页新增“策略”页签：Host 只读汇总、按 Source 编辑主 Realm / 额外 Realm、删除策略、查看变更。
- 生产代码删除 `LegacyHostPolicy`；11a 语义断言保留在测试辅助包 `internal/v2auth/v2authtest` 与 `legacy_test.go`，gateway/probe/runner 的注入式测试改用测试辅助包。
- 审计：策略修改/删除写入管理审计（`policy_update` / `policy_delete`，detail 含 host 与旧→新 Realm），并写 `source_events(kind=policy_change)`。

### 12-F1 Host 关闭隔离

- `internal/registryhost.Match(patterns, host)`：统一精确 Host 与 `*.pkg.dev` 的 Artifact Registry 匹配。
- Gateway 的 `multiOriginHost` 改为调用同一函数。
- `HostProbeOptions.AllowedHosts` 来自 `config.registry.multi_origin_hosts`，在 `jobs()` 取到任务后、执行探测前过滤。
- `reconcileRepos` 职责不变：只清理能力结论，不探测、不写健康状态。
- `docker.io` / `ghcr.io` 仍由 `ListDueHostProbes` 的 SQL 排除，不受白名单影响。

### 12-F2 调度缓存 0 窗口

- 代码无需修改：`main.go` 已接线 `eng.OnChange(sched.Invalidate)`，API 入口均调用 `s.eng.Changed()`。
- 新增端到端测试：PATCH 源启停后，`scheduler.Candidates` 在下一次调用立即看到新状态，`ListTTL` 设为 60s 以排除自然过期。

### 12-T 链路测试

- 新增 `TestMultiOriginSecondSourceFailoverKeepsDigest`：两个 Source，首选 503，第二源 200；断言响应体、`Docker-Content-Digest`、`X-ML-Source` 指向第二源，官方回源次数为 0。
