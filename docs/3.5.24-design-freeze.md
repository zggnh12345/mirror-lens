# Mirror Lens 3.5.24 G1 设计冻结结论

前置：G0 四项取证完成（见 `docs/3.5.24-evidence-baseline.md`）。G1 本轮交付**设计冻结与风险裁定**，不含代码实现。
状态：**DESIGN_FROZEN（三身份语义已澄清；下列"需实现"项为冻结目标，非现状）**。

## 1. 三个业务身份（冻结，不得混同）

审查指出早期稿件把"实际连接地址"和"缓存/认证身份"都叫 Endpoint，是当前最重要的语义冲突。3.5.24 必须把下面三个身份分开；底层可复用同一个不可变的规范化端点**值结构**（Scheme + CanonicalHost + EffectivePort），但三者是**不同业务身份，不得当成同一个对象**。

| 业务身份 | 含义 | 是否含端口 | 典型值 |
|---|---|---|---|
| `RegistryIdentity` | 客户端请求的**逻辑 Registry 站点身份**；用于 repo_host、策略 Host、凭据 Host、状态关联 | 否（纯逻辑 Host，不含 scheme/端口） | `ghcr.io`、`quay.io`、`registry.example.com` |
| `SourceEndpoint` | `sources.base_url` 对应的**实际镜像节点连接地址**（调度选中的回源目标） | 是（Scheme + 域名/IP + EffectivePort） | `https://mirror.example.com:5443`、`http://<IP>:5000` |
| `Origin` | 重定向/凭据转发安全判断所用的**来源三元组**（Scheme + CanonicalHost + EffectivePort） | 是（完整三元组） | `https://registry.example.com:443` |

约束：
- `RegistryIdentity` **不含 IP 字面量示例**。当前 `registryhost.checkHost`（`registryhost.go:54-75`）明确拒绝带端口 Host 与 IP 字面量；repo_host / 策略 Host / 凭据 Host 都依赖逻辑 Registry 身份模型。IP 属于 `SourceEndpoint`，**不得**因 SourceEndpoint 是 IP 就写进 repo_host 或凭据身份字段，**不得**用 `net.ParseIP(host) != nil` 直接放行 `Allowed()`。用户添加的是 IP 镜像节点，不是把逻辑 Registry 身份改成 IP。
- `SourceEndpoint` 是 `sources.base_url` 的规范化连接地址（含 Scheme、域名或 IP、EffectivePort）。它**不是** RegistryIdentity，也不是客户端请求的逻辑 Registry。
- `Origin` 是凭据安全判断的 Scheme+CanonicalHost+EffectivePort 三元组；凭据转发必须调用完整 Origin 比较，**不得**降级为 Host 比较。
- IPv6 规范化与 safehttp `Unmap()` / IPv4-mapped 保持一致；默认端口 80/443。

**裁定 ①（复现值结构，但三身份分离）**：
- 组成字段相同的部分（Scheme + CanonicalHost + EffectivePort）用一个不可变、规范化强类型端点值结构表达，不维护多套等价结构。
- 但 `RegistryIdentity`（逻辑、去端口）、`SourceEndpoint`（实际连接目标）、`Origin`（凭据安全来源）是不同的业务身份与不同的比较函数，禁止互换或降级比较。
- 凭据转发用完整 `Origin` 比较（Scheme+Host+Port 三项）；Host 级 Realm Policy 单独用 `CanonicalHost` 比较（去端口），不走 Origin。

## 2. 两个"同 Host"语义（写死，不得混用）

- **Realm/Policy 判定** → 去端口的 CanonicalHost（`registryhost.Normalize(u.Hostname())`）。
- **凭据转发同源判定** → 完整 Origin（Scheme+CanonicalHost+EffectivePort，即含端口的 `.Host` + scheme）。
- 现状混用点（须修正）：`identity.go:251`、`gateway.go`（applyRedirect/recheck）、`registryauth.go:244`、`csrf.go:59`（csrf 已正确比较 scheme+host+port 三项）。
- **A3 机制边界（本轮纠正）**：Realm 授权（`PolicySnapshot.Allows`，`policy.go:73-97`）与 Token 跳转（`RedirectPolicy`，`identity.go:221-265`）是**两套独立判断**。前者比 Challenge Realm 与策略自身 `p.Scheme`/`p.Realms`，不读原始 Registry 请求 scheme；后者的 sameOrigin/`:254` 只管 Token 服务的 3xx 跳转。不得用后者推导前者的结论。

## 3. 重定向裁定（冻结）

- HTTPS→HTTP：拒绝（任何 kind）；实现窄范围 HTTP 例外时须重构 `identity.go:242/:248` 判断顺序，使降级门禁重新有效（`:248` 当前被 `:242` 遮蔽为死代码）。
- HTTP→HTTP 同 Registry Host：允许（须过 `PolicySnapshot.Allows`）。
- HTTP→HTTP 跨 Host：拒绝。
- HTTP→HTTPS：允许升级，不自动复制 Authorization。
- 每跳过 safehttp + 每跳重查目标策略（**G1 目标，需实现**）。
- Blob CDN 跨 Host/端口重定向不携带 Authorization。
- **Token Realm 与普通 Redirect 拆调用上下文**，独立测试锁定；禁止全局放宽 HTTPS-only。
- **现状 vs G1 目标差异（C2，必须显式记录）**：当前 `recheckRedirectPolicy`（`gateway.go:715`）在 Scheme/Host 改变时 `:719` 直接 `return nil`，**不重解析目标策略**，仅同 Host/Scheme 才重查。这是实现阶段必须补的变更点，不能写成现状已满足"每跳重查"。

## 4. 凭据裁定（冻结）

- HTTP Endpoint 显式配置 = 授权该 Endpoint 明文凭据（含 Basic）。
- **明文凭据安全警告（需实现 UI 提示）**：允许显式配置 HTTP Endpoint 时，Token Realm 即使是 HTTPS，也**不能保护随后发往 HTTP Registry 的 Authorization**——Basic 凭据 / Bearer Token 到 HTTP Registry 仍可能被链路窃听。UI 必须明示该风险，不得把"Token Realm 是 HTTPS"展示成整条认证链已安全。
- **Realm 授权矩阵（按机制边界，保留安全升级路径）**：
  - HTTP Registry + 同 Host HTTPS Realm：**允许**（前提 HTTPS Realm 在允许列表；`Allows` 比的是 Realm 自身 scheme 与 `p.Scheme`，与 Registry 请求 scheme 无关）——**保留此路径，不得改为一律拒绝**。
  - HTTP Registry + 同 Host HTTP Realm：当前 `normalizeRealm` 写入层拒绝；新增窄例外仅限"明确配置 HTTP 的 Registry + 同 CanonicalHost 的 HTTP Realm"。
  - HTTPS Registry + 同 Host HTTP Realm：**拒绝**（绝不 HTTP Token Realm）。
  - 跨 Host Realm：拒绝。
- 跨 Origin 不自动复制认证头。
- Host 级凭据映射跨端口共享 = 已接受限制，须写兼容说明。
- `DefaultRealmsFor(IP) = nil` 不动；不扩 `hostProfiles`（gcr.io/quay.io）。
- fail-closed 保留：`AuthorizeCredential` 五条件门禁不削弱。

## 5. Manifest 缓存（冻结）

- **默认身份 = 请求规划期确定的完整 `RegistryEndpoint`**：Manifest CacheKey 按请求的逻辑 Registry Endpoint（Scheme + CanonicalHost + EffectivePort，即 `scheme://host:port`）构造。该值在请求规划期由**请求上下文**确定（客户端请求的协议、逻辑 Host、显式或默认端口），**不是调度选中的 `SourceEndpoint` 镜像节点地址**，因此同一 Registry/Repo/Ref 不随后端镜像节点漂移。此口径以最终版任务书 §0.2、§1 为准；覆盖早期"按逻辑 RegistryIdentity（裸 host）建键"的口径。
- **不得**把调度选中的 `SourceEndpoint`（`sources.base_url` 指向的实际回源节点）写进 Manifest CacheKey：节点地址在规划期尚未选出，纳入后同一请求在不同节点下产生不同键，破坏跨节点共享缓存，并可能把内网 IP 泄漏进缓存键。规划期 `RegistryEndpoint` 与调度期 `SourceEndpoint` 两者必须分开。
- **Key 格式演进（按实测，不存在 `docker:m:0:`）**：
  - 旧（epoch=0）：`docker:manifest:<裸host>/<name>:<ref>|accept=…`（`credwrite_test.go:156` 锚定）。
  - 当前（epoch>0）：`docker:m:<epoch>:<裸host>/<name>:<ref>|accept=…`。
  - 3.5.24（冻结目标）：`docker:m|manifest:<epoch>:<scheme://host:port>/<name>:<ref>|accept=…`——即在上述键的 rest 段把裸 host 换为完整 `RegistryEndpoint`（scheme + host + effective port）。任务书预设样例 `docker:m:0:https://...` 中的 `docker:m:0:` 前缀按实测不成立（epoch=0 走 `docker:manifest:`，`docker:m:` 要求 epoch>0；完整格式以 epoch>0 路径为准），不照抄该样例。
- **升级影响（已验证 + 冻结口径）**：因 Key 由裸 host 变为完整 Endpoint，所有既有域名 Registry 的旧格式 Manifest 缓存**必然无法命中**新格式 Key（`CacheGet` 精确键查询、无旧 Key 回退，见 G0-4）。每个尚未重建的新 Key 在升级后**第一次请求各自回源 Miss 并重建该 Key**——按 Key 计数，**不得**写成"每个 Registry 只回源一次"。旧记录不主动清空，按原 TTL/GC 自然回收。Blob Digest Key 与 `CacheEpoch` 不变，Blob 热缓存仍可复用；私有认证请求在共享缓存查询前 bypass，不计入此项。不得用 epoch bump 触发重建。
- 热缓存性能对照：两版本各自先完成自己的 Manifest 缓存预热，再测热缓存；3.5.24 升级后的首次回源/重建请求记为 `manifest_key_rebuild_first_miss`，作为一次性缓存重建成本单独披露（回源次数与耗时），不混入热缓存命中样本。
- **未验证项（单独保留）**：生产 `cache_epoch` 实际值——未读取，不推断生产当前前缀。（读路径"无旧 Key 兼容查找"已由 `CacheGet` 精确查询验证，不再列为未验证。）

## 6. 准入与安全底线（冻结）

- 三分准入：产品准入 / safehttp / 凭据提供者资格；不扩 hostProfiles。
- 不改 DB Schema/索引/约束/Schema Version；不迁移或重加密凭据；不改 AEAD AAD 格式。
- 不把端口并入 Registry Host 身份；不扩 hostProfiles 名单；不递增 Cache Epoch、不清 Blob。
- 不加 HTTPS 降级；不默认放行私网/回环/链路本地/组播/保留地址。
- safehttp 完整保留不旁路，每跳重定向重查目标 IP。
- `Allowed()` 禁止 `if net.ParseIP(host) != nil { return nil }` 式裸放行。
- **tlsInfo 拆分（需实现，验收项）**：当前 `tlsInfo`（`probe.go:129-164`）固定 `net.JoinHostPort(host,"443")`，而 `hostOf(base)`（`:181-188`）保留显式端口与 IPv6 方括号——对 `https://host:5443` 会二次拼 443 导致拨号错误。冻结要求：
  - 连接地址与证书验证名分离：实际连接端口来自 `SourceEndpoint`，域名验证名用规范化 Host。
  - IPv4 / IPv6 / 域名均有测试；IPv6 方括号不得重复处理。
  - HTTP BaseURL 不调用 tlsInfo（当前对 HTTP 仍调用，产生错误 TLS 诊断）。
  - HTTPS 默认端口与非默认端口分别测试；证书校验错误与网络不可达分开报告。
  - 该缺陷影响 TLS 诊断与非默认端口证书检查路径，不等于下载请求必然失败（实际探测请求用完整 BaseURL）。

## 7. 五条底线（冻结）

数据库不变；单轨升级；单事务原子性（"本次没有数据库迁移事务""数据库升级事务数量为零"）；Blob 不变（Digest Key/Epoch 不变）；旧功能不退化（旧 Key 首次回源属已披露影响，新 Key 预热后热缓存性能须过对照阈值）。

## 8. 风险裁定

| 风险 | 等级 | 处置 |
|---|---|---|
| SourceEndpoint / RegistryIdentity / Origin / 规划期 RegistryEndpoint 多身份混同 | 高 | 三身份分离定义与比较函数；Manifest CacheKey 用规划期完整 RegistryEndpoint（scheme://host:port，来自请求上下文、非调度 SourceEndpoint），不随后端节点漂移；独立测试锁定，禁用调度结果当缓存键 |
| HTTPS-only 前置门共用，拆分不彻底会放宽 HTTPS→HTTP | 高 | 强制拆上下文 + 矩阵逐项 RED-GREEN；重构 `:242/:248` 顺序使降级门禁有效 |
| Realm 授权与 Token 跳转机制混用导致误判 | 高 | 严格区分 `Allows`（`policy.go:73-97`）与 `RedirectPolicy`（`identity.go:221-265`），独立测试锁定 |
| 每跳策略重查现状缺失（跨 Host/Scheme 直接 return） | 高 | `gateway.go:719` 变更点写入实现门槛，RED-GREEN 锁定 |
| Realm 端口忽略是目标非现状（Allows 用 realm.Host 含端口，normalizeRealm 去端口） | 高 | 按 §2 六项测试 RED-GREEN；忽略端口仅指 Realm 身份，实际连接目标仍经 safehttp 独立检查 |
| tlsInfo 固定 443 + hostOf 保留端口致自定义端口/IPv6 证书探测错误 | 中 | 按 §6 拆分连接地址/验证名，IPv4/IPv6/域名、HTTP 分支、默认/非默认端口分别验收 |
| IPv6 字面量被 `api.go:694` `Contains(".")` 误拒 | 中 | 实现阶段修校验；G0-1 载体已存在，不阻断 |
| Manifest 键换格式导致全量首次回源 | 中 | 已验证无旧 Key 回退；按 Key 计数；预热后测热缓存；不 bump epoch |
| HTTP Endpoint 明文凭据被链路窃听 | 中 | UI 明示 Basic/Bearer 明文传输风险，不得将 HTTPS Token Realm 展示为整链安全 |
| 生产容器形态下公网 IPv6 / IP SAN 证书 / 后端 IP:Port 直连缺失 | 中 | G0-3 分层标注（宿主 PASS、生产容器 BLOCKED）；不得以 fakeip/保留地址冒充 |
| Host 级凭据跨端口共享 | 低 | 已接受取舍，写兼容说明 |

**裁定 ②（Realm 端口维度）——保持 Host 级，端口忽略是"需实现"目标**：
- Realm 授权按 `CanonicalHost` 比较（去端口），忽略端口；与 Host 级策略/凭据绑定一致。当前 `Allows` 用 `realm.Host`（含端口，`policy.go:80/:86`）而 `normalizeRealm` 去端口（`store/policy.go:387-400`），存在语义差异——必须实现后才有"忽略端口"行为。
- 实际发起 Token 请求时，**Challenge URL 中的端口必须原样保留**，由 safehttp 检查实际连接目标。忽略端口仅指 Realm 身份维度，**不等于**忽略实际连接目标的安全检查。
- `normalizeRealm` 保留去端口语义；HTTP Realm 例外仅按裁定 ①/④ 的范围放宽，HTTPS Registry 路径绝不放宽。
- 必须写入的 Realm 测试（RED-GREEN）：

| 场景 | 期望 |
|---|---|
| 同 Host、无显式端口 | 按策略正常匹配 |
| 同 Host、显式默认端口 | 按 CanonicalHost 匹配 |
| 同 Host、非默认端口 | Realm 身份仍按 Host 匹配（忽略端口） |
| 跨 Host | 拒绝 |
| Token 实际请求 | 保留 Challenge URL 真实端口 |
| 实际连接目标 | 经 safehttp 检查 |
