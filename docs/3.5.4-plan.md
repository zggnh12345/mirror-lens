## 二、步骤

### S0 迁移安全（阶段 0）

**S0.1 单实例锁（D0）**

- 新增 `internal/store/lock.go`：`<data>/mirror-lens.lock` 上 `flock(LOCK_EX|LOCK_NB)`。
- 在所有可能打开同一 data-dir 的启动入口获取（主程序、导入/种子工具、运维子命令），不只在迁移函数里加锁；
  失败时输出持锁 PID 并 `exit 1`，锁内写入 pid 与版本便于排障。
- 验收：同一 data-dir 启第二个进程（含工具路径），立即退出且不修改数据库。

**S0.2 迁移前快照（M1）**

- 复用 `internal/store/backup.go` 的 `BackupTo`（`VACUUM INTO`）。
- `Store.migrate()` 先探测 pending steps；有 pending 才快照到
  `<data>/backup/pre-<version>-<ts>/mirror-lens.db`。
- 磁盘预检：`需要 = (db + wal) × 1.2 + 64MB`，用 `statfs` 判断；不足则迁移前失败。
  该公式是最低安全余量，不是对任意库的空间保证；快照实际写入失败同样必须阻止迁移。
- 验收：快照文件存在、`PRAGMA integrity_check` 为 ok、迁移失败时可从该文件恢复。

**S0.3 成对备份（M2）**

- 同一目录复制 `secret.key`，权限 0600；写 `manifest.json`（两个文件的 sha256、版本、时间）。
- DB、`secret.key`、`manifest.json` 是一个恢复单元：任一缺失或校验失败即视为无效，必须阻止继续迁移。
- 备份目录权限要让服务运行用户可读，否则恢复时读不到（当前生产 `pre-3.5.3` 目录为 root:root 0705，需注意）。
- 验收：缺 `secret.key` 的备份视为无效，启动/恢复脚本必须拒绝。
- 权限演练必须用实际服务运行用户（非 root）：目录遍历、文件读取、恢复写入、恢复后权限各验一次；
  仅以 root 测试成功不算通过。

**S0.4 迁移 checksum（M3）**

- `schema_migrations` 增加 `checksum TEXT NOT NULL DEFAULT ''`（`store.go:217` 建表处 + 兼容 ALTER）。
- 首次登记时写入 `sha256(name + version + canonical_definition)`；`Description`、`AppVersion` 不参与。
- 已登记步骤 checksum 不一致时 fail-fast，提示“新增迁移版本，不要原地改”。
- 验收：故意改一个已发布步骤的 SQL，启动必须失败。

**S0.5 日志与观测（M4）**

- 删除 `already_done` 假字段；runStep 日志只输出真实执行结果与耗时。
- 验收：干净库、重复启动各跑一次，日志字段与行为一致。

### S2 模型与迁移（阶段 2）

产出 D3，然后按 D3 实现。

- 加列：`ALTER TABLE sources ADD COLUMN registry_identity_state TEXT NOT NULL DEFAULT 'unclassified'`；
  是否加 `CHECK` 以目标 SQLite 版本实测为准（需重建表则不做），退到应用层校验时，
  所有写入路径（`AddSource`、导入、种子、更新、测试辅助）都必须经过同一校验函数，不能只依赖迁移后断言。
- 迁移步骤（一个 step，事务内）：34 条写 `docker.io` + `identified`；9 条写 `not_applicable`；
  id 114/115 仅补 `identified`（Host 与能力不动）；46 条不写身份字段，保持默认 `unclassified` 与空 Host。
  写 `schema_migrations`；失败整体回滚。
- 幂等：以 `name` 为主键，重复启动不重复执行；已识别的行不重复覆盖。
- 迁移后校验：`repo_host='' AND registry_identity_state='identified'` 必须为 0；
  `repo_host<>'' AND registry_identity_state<>'identified'` 必须为 0。
- 验收：真实库副本上迁移一次、重启两次，行数与身份分布不变。

### S3 新增入口与 Probe 隔离（阶段 2）

- `AddSource`（`store.go:803`）：仅对 **Docker Registry 来源**且未显式指定 Host 的新增源映射 `docker.io` + `identified`；
  非 Registry 来源按类型写 `not_applicable`；无法判定类型时拒绝创建或写 `unclassified`，不得默认映射到 Hub。
- `SetRepoHost`（`host.go`）必须同事务写 `registry_identity_state='identified'`，否则改完 Host 身份仍停在 `unclassified`。
- 同版检查全部写入路径：导入、种子、更新源、测试辅助、其他直接写 `sources` 的代码。
- `ListDueHostProbes`（`host.go:463`）：准入条件为
  `registry_identity_state='identified' AND repo_host<>'docker.io' AND repo_host<>'ghcr.io'`；
  空 Host、`unclassified`、`not_applicable` 一律排除。仅排除两个 Host 名不够。
- 新通道入口（`registryCandidatesRaw` 之前）：同样的 Host 分类校验；确认无绕过调用。
- `recovery_seed.go:59-63` 也是准入路径：当前只按 `repo_host<>'' AND <>'ghcr.io'` 建恢复行，
  不看能力与身份。必须同版加身份门禁，否则新库/无 seed 标记的副本会给 Hub 源建 `docker.io` 恢复行。
  生产当前 `recovery_seed_v1=1`、`registry_host_recovery` 为 0 行，现网不会立即触发，但不能依赖这个巧合。
- **不改** `SourceCandidates("docker")`、`SourceCandidates("ghcr")`。
- 验收：
  - 不传 Host 新增源 → 库里 `repo_host='docker.io'`；
  - 迁移后 `registry_host_gen` 无 `docker.io`、`registry_host_recovery` 无 `scope='docker.io'`；
  - `SourceCandidates("registry:docker.io")` 为空。
